# 🍏 Руководство по MLX на Apple Silicon для чайников

Добро пожаловать в мир **MLX**! Если вы привыкли к Ollama и хотите понять, как устроен MLX на вашем Mac и как с ним работать без головной боли — это руководство для вас.

---

## 1. Что такое MLX и почему это магия? ✨

Раньше на обычных компьютерах видеокарта (GPU) и процессор (CPU) имели разную память. Чтобы запустить нейросеть, нужно было сначала загрузить её в оперативную память, а потом «перевозить» данные в память видеокарты. Это как склад и цех в разных зданиях — работает, но логистика съедает кучу времени.

На Mac с процессорами **Apple Silicon (M1, M2, M3, M4)** память **общая (Unified Memory)**. Процессор, графика и нейропроцессор (Neural Engine) «едят из одной тарелки». 

**MLX (Machine Learning Explore)** — это официальная библиотека от команды Apple, написанная специально для того, чтобы локальные нейросети летали на чипах Apple Silicon.
* **Скорость:** MLX обращается к общей памяти напрямую через графический движок Metal, выжимая максимум из вашего графического процессора.
* **Эффективность:** Никакого лишнего перекладывания данных. Меньше задержек, больше токенов в секунду.
* **Лёгкость:** Никаких тяжелых фоновых программ (сервисов-демонов), которые постоянно висят в фоне и едят оперативку.

---

## 2. MLX против Ollama: В чём разница? ⚖️

Если в Ollama всё спрятано под капот, то в MLX всё прозрачно, гибко и открыто:

| Критерий | Ollama | MLX |
| :--- | :--- | :--- |
| **Откуда берутся модели** | Из встроенной библиотеки Ollama. | **Напрямую с Hugging Face** (главный мировой сайт с нейросетями). |
| **Где лежат файлы** | В скрытой папке Ollama (`~/.ollama`). | В стандартном кэше Hugging Face (`~/.cache/huggingface/hub/`). |
| **Фоновые процессы** | Всегда запущен демон Ollama, который ест ресурсы. | Запускается **только внутри приложения** (например, сервера Л.Е.С.) и закрывается вместе с ним. |
| **Имя модели** | `qwen3:14b` | `mlx-community/Qwen3.5-9B-OptiQ-4bit` |

## 3. Карманный справочник команд (Командная строка) 🛠

Все команды выполняются в терминале вашего Mac. Перед запуском команд рекомендуется активировать виртуальное окружение проекта:
```bash
source .venv/bin/activate
```

### 🔎 Как посмотреть, какие модели уже скачаны?
Все модели MLX лежат в кэше Hugging Face. Чтобы увидеть список загруженных моделей и сколько места они занимают:
```bash
huggingface-cli scan-cache
```

### 🗑 Как удалить модель и освободить место?
Если модель больше не нужна, вы можете удалить её интерактивно (утилита предложит выбрать, что стереть):
```bash
huggingface-cli delete-cache
```

### 📥 Как скачать модель вручную?
Обычно система скачивает модель сама при первом обращении. Но если вы хотите скачать её заранее (например, при хорошем интернете):
```bash
/Users/ovc/Projects/LES_v2/.venv/bin/python3 -c "from huggingface_hub import snapshot_download; snapshot_download('mlx-community/Qwen3.5-9B-OptiQ-4bit')"
```

### 💬 Как быстро пообщаться с моделью прямо в терминале?
В библиотеку `mlx-lm` встроен очень удобный режим чата для тестов:
```bash
python3 -m mlx_lm.chat --model mlx-community/Qwen3.5-9B-OptiQ-4bit
```
*(Для выхода из чата нажмите `Ctrl + C`)*

## 4. Настройка локальной модели в Cline (Roo Code) 🤖

Чтобы использовать вашу крутую 9B модель в плагине **Cline** (VS Code), укажите в его настройках следующие параметры:

1. **API Provider**: Выберите `OpenAI Compatible` (или `Custom OpenAI API`).
2. **Base URL**: `http://127.0.0.1:8080/v1` (это адрес нашего локального сервера Л.Е.С. MLX Host).
3. **Model ID**: `mlx-community/Qwen3.5-9B-OptiQ-4bit` (или просто выберите её, если подгрузился список).
4. **API Key**: Введите любое слово (например, `local` или `12345`). *Это обязательное требование клиента Cline, хотя наш сервер не проверяет ключи.*

## 5. Как модели управляются внутри Л.Е.С.? 🪵

В нашей локальной экспертной системе управление моделью сделано максимально бережно по отношению к вашей оперативной памяти:

1. **Ленивая загрузка (Lazy Load):**
   При старте системы веса и токенизатор по умолчанию не загружаются. Они «просыпаются» при первом запросе. После загрузки веса остаются тёплыми до TTL, а временный Metal-кэш prefill/decode очищается после каждого хода.
   Отдельный bounded KV/prefix cache хранит только стабильные границы уже
   завершённых chat-сообщений. Он не является историей сессии: история
   передаётся клиентом, а cache лишь не пересчитывает её общий токеновый префикс.
   При выгрузке/смене модели этот cache полностью очищается. Лимиты задаются
   `MLX_PROMPT_CACHE_MAX_ENTRIES` (по умолчанию `4`) и
   `MLX_PROMPT_CACHE_MAX_BYTES` (по умолчанию `1 ГБ`).
2. **Автоматическая выгрузка (TTL - Time to Live):**
   На целевом Mac с 24 ГБ основная 9B остаётся тёплой до часа (`MLX_MAIN_TTL_SEC=3600`).
   Это убирает повторную холодную загрузку между обычными вопросами. Memory guard предупреждает
   ниже 6 ГБ доступной RAM и выгружает main только ниже 4 ГБ либо при swap выше 85%.
   На macOS накопленный swap не считается текущим давлением, если доступно не менее 5 ГБ RAM:
   система может не освободить старые swap-файлы сразу, и из-за этого нельзя циклически выгружать
   тёплую модель.
3. **Управление через `.env`:**
   Чтобы сменить модель в Л.Е.С., достаточно открыть файл `.env` в корне проекта и изменить параметры:
   ```ini
   LLM_MODEL=mlx-community/Qwen3.5-9B-OptiQ-4bit
   MLX_MODEL=mlx-community/Qwen3.5-9B-OptiQ-4bit
   VALIDATOR_BACKEND=rules
   ```
   После изменения файла просто перезапустите службу `mlx` в терминале:
   ```bash
   python3 tools/les_runtime_control.py restart mlx
   ```

4. **Настоящий stream и диагностика:**
   `/v1/chat/completions` при `stream=true` отдаёт реальные токены по мере генерации.
   MLX Host пишет в лог `ttft`, скорость prefill (`prompt_tps`), скорость decode
   (`generation_tps`) и peak memory. Долгая пауза до первого токена означает
   cold load или тяжёлый prompt; медленный вывод после первого токена означает
   проблему decode. Это разные дефекты и чинятся по-разному.
   Для non-stream OpenAI-ответа число повторно использованных токенов доступно
   в `usage.prompt_tokens_details.cached_tokens`. На isolated Qwen 3.5 9B probe
   второй ход использовал `14 968` токенов общего префикса из `14 996` и занял
   `2,24 с` после холодного хода `139,17 с`.

   Штатная проверка ответа выполняется детерминированным `rules`-валидатором. Отдельная
   validator-LLM не загружается и не выталкивает основную 9B из памяти между вопросами.

5. **Измеренный выбор 9B:**
   На Mac mini M4/24 ГБ прогретый `mlx_lm benchmark` с `512` входными и `384`
   выходными токенами дал для OptiQ `152,5 tok/s` prefill и `11,19 tok/s` decode
   при peak `7,84 ГБ`. Uniform 4-bit дал `91,1/7,19 tok/s` при `5,78 ГБ`.
   Поэтому OptiQ — основной профиль качества/скорости, а uniform остаётся резервом
   совместимости. Это raw inference; RRF, reranker и длинный evidence имеют отдельную задержку.

6. **OptiQ MTP пока не production:**
   Изолированный `mlx-optiq==0.3.3` ускоряет greedy (`5,20` против `3,71 tok/s`), но его
   OpenAI MTP hook теряет request sampler и молча исполняет greedy. После диагностического
   исправления настоящий production sampler дал p50 `3,83 tok/s` и wall `113,74 с` против
   stock `3,73 tok/s`/`114,95 с`: только `+2,6%` decode и `-1,1%` wall при acceptance
   `67,4%` и peak `8,82 ГБ`. Это ниже обязательных `15%` и порога отказа `10%`. MTP также
   зависит от `seed`, игнорирует server prompt cache и не публикует telemetry через API.
   Поэтому штатный host не переключён. Команды и полный протокол:
   [docs/LOCAL_INFERENCE_OPTIQ_MTP_M4_2026-07-13.md](docs/LOCAL_INFERENCE_OPTIQ_MTP_M4_2026-07-13.md).
