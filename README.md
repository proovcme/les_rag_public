# ЛЕС — локальный помощник ГИП/РП

ЛЕС помогает разбираться в многолетних проектных документах, письмах, таблицах и чертежах. Когда пользователь выбрал датасет или вложения, они становятся источником истины: модель получает RAG, показывает доказательства и честно говорит, если ответа в источниках нет. Без выбранных источников ЛЕС может работать как обычный локальный ИИ в harness.

Главный принцип: **модель исследует и связывает, RAG даёт правду, инструменты читают и действуют, код считает и оформляет, решение принимает человек**.

## Из чего состоит система

| Узел | Назначение | Где может работать |
|---|---|---|
| **Совушка** | Чат, загрузка файлов, просмотр данных и конфигурация | В Tauri-приложении, обычном браузере или установленной PWA |
| **Backend ЛЕС** | API, обработка документов, RAG, память, инструменты и контроль доступа | На той же машине или отдельном узле |
| **Модель** | Формирование ответа и выбор разрешённых инструментов | Локально, в LAN/ZeroTier или в облачном API |
| **Qdrant** | Векторный индекс документов и native dense+sparse RRF | Как отдельный локальный или сетевой сервис |

Компоненты не обязаны находиться на одном компьютере. Поддерживаются три runtime-профиля:

- `full` — Совушка и backend вместе;
- `backend` — только headless API ЛЕС;
- `ui` — только Совушка, подключённая к указанному backend.

Tauri запускает обычный полный профиль. Раздельные профили уже реализованы как операторские точки входа; готового мастера развёртывания Совушки на VPS в этом выпуске ещё нет.

## Что готово в 0.30.1

- Windows 10/11 x64 installer с собственным офлайн Python/uv runtime;
- Совушка для desktop, browser и PWA с адаптивной мобильной компоновкой;
- загрузка и индексация PDF, DOCX, XLSX, CSV и других поддерживаемых документов;
- единая contract-versioned Qdrant collection с именованными `dense` и `bm25_sparse` векторами;
- production retrieval через native RRF, lexical safety channel и parent/context expansion;
- ответы по выбранным датасетам и файлам с источниками;
- отдельный просмотр документов и извлечённых фрагментов без вызова модели;
- реестр подключений моделей с отдельными ролями «Ответы», «Эмбеддинги» и «Запасная модель»;
- OpenAI-compatible endpoints на loopback, в частной сети и через HTTPS;
- masked-хранение API-ключей и явное подтверждение сетевых подключений;
- память проекта и ограниченный инструментальный цикл без неявного доступа ко всему корпусу;
- транзакционное Windows-обновление с изолированной проверкой и каталогом отката;
- кумулятивный GitHub patch-updater: полная 0.30.0 обновляется до последней совместимой версии одним небольшим ZIP.

Без Qdrant ЛЕС и Совушка запускаются, но поиск по проиндексированным документам недоступен. Без модели можно просматривать данные и настраивать систему, но нельзя получить модельный ответ.

## Что пока не считается готовым

- **качество RAG** ещё требует прозрачной live-приёмки на нескольких реальных корпусах: хороший ответ сам по себе не доказывает, какой evidence получила модель;
- **Студия документов** сохранена в коде, но скрыта из production-навигации как недоделанная;
- **CAD/BIM** принимает подготовленные проекции, но пользовательский production-экран скрыт до отдельной приёмки;
- **почта** имеет отдельный intake-контур, но не заявляется готовым основным пользовательским workflow;
- **развёртывание Совушки на VPS** архитектурно поддерживается разделением UI/backend, но пока требует операторской настройки;
- **macOS и Linux** остаются reference/server-контурами, а не равноправными публичными desktop-выпусками;
- Windows installer пока не подписан Authenticode.

Наличие внутреннего модуля или API в репозитории не означает, что функция уже доступна пользователю или прошла product acceptance.

## Модели и внешние сервисы

`LES-Setup.exe` не содержит модели, Ollama, FreeToken, Lemonade, Qdrant или Docker. Это внешние пользовательские компоненты.

| Роль | Поддерживаемый контракт |
|---|---|
| Ответы | Ollama, FreeToken, Lemonade и другие OpenAI-compatible API |
| Эмбеддинги | Отдельный OpenAI-compatible embedding endpoint; проверенный профиль — BGE-M3, 1024 измерения |
| Индекс | Qdrant по HTTP, локально или по доверенной сети |

Docker не является частью lifecycle ЛЕС и не требуется приложению. Если пользователь запускает Qdrant в контейнере, это только один из возможных способов эксплуатации внешнего сервиса.

Облачная модель получает текст запроса и переданный ей контекст. ЛЕС не должен переключать локальную модель на облачную или отправлять документы наружу без явной пользовательской конфигурации. Подробнее: [границы данных](docs/public/privacy-and-data-boundaries.md).

## Установка на Windows

1. Откройте [последний публичный выпуск](https://github.com/proovcme/les_rag_public/releases/latest).
2. Скачайте `LES-Setup.exe` и `LES-Setup.exe.sha256`.
3. Сверьте SHA-256 и запустите установщик.
4. Откройте ЛЕС и настройте отдельно модель ответов, эмбеддинги и Qdrant.

Права администратора, Git и системный Python не нужны. Первый запуск разворачивает встроенную среду. Пользовательские данные находятся в `%LOCALAPPDATA%\LES`, а заменяемая программа — в `%LOCALAPPDATA%\Programs\LES`.

Windows может предупредить о неизвестном издателе, потому что текущий тестовый выпуск не имеет Authenticode-подписи. Загружайте установщик только со страницы GitHub Releases и сверяйте checksum.

Инструкция по сбоям: [диагностика Windows](docs/public/windows-troubleshooting.md).

## Проверяемая граница результата

ЛЕС должен отличать найденный факт от вывода модели. Число без источника или воспроизводимого расчёта не считается подтверждённым результатом. Если документов, строк, единиц или входных данных недостаточно, система должна вернуть `MISSING`, `BLOCKED` или явное предупреждение, а не дополнить ответ догадкой.

Специализированные строительные модули присутствуют в репозитории, но не являются скрытым «сметным ядром» текущего чата и не выбирают профессиональное решение вместо модели или человека.
