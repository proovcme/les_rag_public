# Быстрые обновления ЛЕС через VPS

## Назначение

Начиная с `0.24.16 / build 427`, любой установленный Windows-ЛЕС получает ручной канал
совместимых исправлений с `https://les.ovc.me/updates/`. Legion является полигоном приёмки, но не
особым адресатом: клиент работает из собственного runtime и `%LOCALAPPDATA%` каждой машины.

Оператор нажимает `Проверить патч` → `Установить`. Фоновых проверок и самопроизвольной установки нет.

## Что разрешено

- Python под `backend/`, `proxy/`, `sovushka/`;
- prompts/skills и безопасные JSON/YAML/Markdown/UI assets;
- корневые `proxy_server.py` и `sovushka_ng.py`.

Зависимости, lock-файлы, схемы/миграции, baseline ФСНБ, installers, Rust/Tauri/NSIS и нативные
компоненты запрещены allowlist одновременно у builder и у клиента. Они требуют полного выпуска.

## Контракт безопасности

`latest.json` содержит `base_commit`, `target_commit`, список файлов, старый и новый SHA-256 каждого
файла, SHA-256 и размер архива. Клиент принимает только HTTPS `les.ovc.me/updates/*`, проверяет
собственные base-хэши до загрузки и повторно перед заменой, сверяет архив с внешним и внутренним
manifest и отвергает лишние файлы/path traversal.

Каждый новый `latest.json` собирается кумулятивно от commit базового полного релиза, а не от
предыдущего патча. Для каждого файла клиент принимает как базовый, так и уже целевой SHA-256.
Поэтому машина может пропустить несколько патчей и затем сразу перейти в последнее состояние;
чужая локальная правка остаётся fail-closed и требует полного выпуска.

Базовый SHA текстового файла считается по фактическому Windows runtime с CRLF, потому что полный
инсталлятор собирается из Windows checkout. Payload хранится как канонический текст; уже обновлённый
файл сопоставляется с target SHA. Это различие обязательно проверяется на установленном runtime.

Helper запускается независимой интерактивной Scheduled Task вне process tree заменяемого runtime:
создаёт backup, останавливает только LES proxy/UI, заменяет подготовленные файлы через `os.replace`,
выполняет `compileall`, запускает новый Tauri runtime второй интерактивной задачей и ждёт
`/api/health` и `/healthz`. При любой ошибке возвращает backup и снова запускает предыдущую версию.
Статус лежит в persistent state и доступен через `GET /api/update/patch/status` после рестарта.

## Публикация

```bash
uv run python tools/vps_patch.py build \
  --base <commit-полного-совместимого-релиза> --target HEAD \
  --file proxy/services/example.py \
  --output dist/vps-patch

uv run python tools/vps_patch.py publish --output dist/vps-patch
```

Builder принимает только явно перечисленные файлы. Публикация сначала загружает `.part`, затем
атомарно переименовывает архив и в последнюю очередь `latest.json`, поэтому клиент не увидит
manifest раньше полного архива.

## Web-контур

`les.ovc.me` больше не проксирует живой API/Совушку. `/` — статический лендинг проекта,
`/updates/*` — origin обновлений; старые `/api`, `/lite-api`, `/les`, `/classic` отвечают `404`.
Рабочие машины доступны только локально/через ZeroTier.

## Live-приёмка

`0.24.15 / build 426` доказал сборку и установку, но его helper унаследовал Windows job-object
Tauri и погибал при остановке UI; публичный feed был немедленно снят. Совместимая база канала —
исправительный полный выпуск `0.24.16 / build 427`, принимаемый отдельным live-патчем на Legion.
