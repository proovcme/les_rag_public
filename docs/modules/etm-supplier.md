# ЭТМ iPRO — коммерческие цены материалов

Кандидат 0.31.199 / 927. Read-only клиент покупателя реализован;
доступ учётной записи оператора к реальному API пока не подтверждён.

## Рабочий путь

1. «Конфигурация → Параметры выполнения»: задайте логин и пароль iPRO в
   маскированных полях, включите «Использовать цены ЭТМ». Перезапуск не нужен.
2. В служебных источниках нажмите «Проверить доступ к ЭТМ». Учётная запись
   сама по себе не подтверждает право читать API.
3. Найдите товар по названию или артикулу и выберите позиции. Показывается
   первая страница, до 20 товаров; при необходимости уточните запрос.
   Можно также ввести уже известные числовые коды ЭТМ.
4. Скачайте «Прайс XLSX»: код, название, единица из карточки, цена без НДС,
   отдельная цена с НДС, артикул, источник и дата. Пропуск — пустая цена с
   причиной, а не нулевая котировка. Текст сохраняется буквально, включая
   имена, начинающиеся со знака формулы.
5. Добавьте файл в существующий датасет «Прайсы» обычной кнопкой добавления.
   Далее действует общий RAG с native RRF, точное чтение и выбор модели.
   Загрузка, индексация и применение цены автоматически не запускаются.

ЭТМ даёт одно предложение одного поставщика. Оно не заменяет достаточный КАЦ,
региональную книгу ФГИС за заданный квартал, труд, машины или нормы работ.
Модель определяет соответствие товара материалу; код не подбирает аналог и
не подтверждает профессиональное решение. Текущая цена не является исторической.

## Контракт и безопасность

Основание: [OpenAPI клиентского API ЭТМ](https://ipro.etm.ru/ns2000/yaml/cli.yaml)
и [схемы](https://ipro.etm.ru/ns2000/yaml/components.yaml). Используется
клиентский `/api/v1`, не торговый `/api/m1`:

- POST `/user/login`: по официальному контракту учётные данные передаются
  в query. Транспортные логи редактируются; секреты не выдаются модели или
  пользователю. Далее `session-id` передаётся заголовком.
- Сессия обновляется за минуту до двухчасового срока; при 403 разрешена
  одна повторная авторизация. Бесконечного повтора нет.
- GET `/catalog`: буквальный запрос оператора, без предметного расширения.
- GET `/goods/{codes}/price?type=etm`: до 50 кодов, интервал между запросами
  цен не менее секунды. Один запрос ЛЕС принимает до 500 кодов.
- Сопоставление исключительно по возвращённому `gdscode`. Чужой код,
  дубликаты цены, отсутствие точной карточки или единицы дают явный пробел.
  Позиционное сопоставление и нулевой прайс не используются.
- Разрешены только HTTPS `ipro.etm.ru/api/v1` и `itest.etm.ru/api/v1`.
  Переадресации, заказы, резервирование и покупки отсутствуют.

`price` — цена без НДС по контракту поставщика, `pricewnds` хранится отдельно;
ставка НДС из этих чисел не выводится. В snapshot нет учётных данных и ключа
сессии. Секреты сохраняются штатным механизмом параметров ЛЕС;
маскированное поле не означает отдельного шифрованного хранилища.

## Точки входа и конфигурация

- `proxy/services/etm_supplier_service.py`: сессия, каталог, котировки,
  безопасные ошибки и XLSX.
- `proxy/routers/service_sources.py`: защищённые POST
  `/api/service-sources/etm/catalog`, `/etm/quotes`; проверка через существующий
  `/{source_id}/process`. Блокирующее чтение выполняется вне event loop.
- `service_source_registry.py`, `config/service_sources.yaml`: `etm_supplier`.
  Чтение статуса не создаёт HTTP-клиента. Зелёный требует успешного чтения при
  текущей конфигурации и непросроченной сессии; ошибка чтения снимает его.
- `runtime_config_registry_service.py`: `LES_ETM_ENABLED` (default 0),
  `LES_ETM_BASE_URL`, `LES_ETM_TIMEOUT_SEC` (1–60), секретные
  `LES_ETM_LOGIN` / `LES_ETM_PASSWORD`. Изменения действуют при следующем
  запросе; смена подключения заменяет клиент.
- `sovushka/pages/instrumenty.py`: существующие `panel`, `text_field`,
  `select_field`, `action_button`, русские статусы и уведомления.

Старые `etm_price_service` и `/api/prices/etm/*` остаются удалёнными.
Новый источник не возвращает альтернативный price island и не меняет inference.

## Проверка и готовность

`tests/test_etm_supplier_service.py`: TTL, auth header, предел 50 кодов,
точная идентичность, единицы и net/gross, безопасные ошибки и логи,
запрет чужого endpoint, literal XLSX, сброс статуса после отказа API.
`tests/test_etm_source_workflow.py`: маскированные GUI-факторы, валидация до
записи, отсутствие ложного зелёного, API, поиск и скачивание. Оба включены
в канонический офлайн-гейт и не обращаются к реальному ЭТМ.

Живая готовность требует ввода учётной записи оператором, успешной проверки,
поиска реального товара и сверки единицы/цены с iPRO. Произвольные ВОР/ЛСР и
новый установщик требуют отдельной профессиональной приёмки: ЭТМ не закрывает
их прежние дефекты.
