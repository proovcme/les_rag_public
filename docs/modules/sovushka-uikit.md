# UI KIT «Совушка»

## Назначение

`sovushka/uikit/` — единственный дизайн-контракт для новых и мигрированных
экранов «Совушки». Как и в Locia, визуальная унификация означает не похожие
одноразовые стили, а общие токены, компоненты, состояния и проверки.

## Источники правды

| Слой | Источник |
|---|---|
| Правила и registry | этот документ |
| Токены и CSS компонентов | `sovushka/uikit/tokens.py` |
| NiceGUI-примитивы | `sovushka/uikit/components.py` |
| Тексты состояний | `sovushka/uikit/states.py` |
| Рабочий процесс агента | `skills/sovushka-ui/SKILL.md` |
| Регрессии и WCAG | `tests/test_sovushka_uikit.py` |

`sovushka_ng._apply_theme()` подключает UI kit после legacy-темы. Новый UI не
добавляет визуальные правила в `sovushka/styles.py`; этот файл остаётся
совместимым историческим слоем до последовательной миграции экранов.

## Реестр компонентов

Новый компонент разрешён только когда ни один из этих примитивов не выражает
его роль:

| Роль | Python/CSS-контракт | Варианты |
|---|---|---|
| Действие | `action_button`, `.sov-ui-button` | `primary`, `secondary`, `quiet`, `danger`; `compact`, `icon_only` |
| Поле | `text_field`, `select_field`, `.sov-ui-input`, `.sov-ui-select` | text/select, label, placeholder, clearable, multiple; label+placeholder не перекрываются |
| Секция | `panel`, `.sov-ui-panel` | `plain`, `raised`, `inset` |
| Заголовок секции | `section_heading` | title + optional detail |
| Статус | `status_badge` | `ok`, `warn`, `error`, `blocked`, `muted` |
| Состояние | `render_feedback_state` | `loading`, `empty`, `error`, `blocked` |
| Айдентика | `acronym_identity` | full, compact |

Страница может добавлять семантический class-hook для layout или поведения, но
не должна локально менять цвет, типографику, radius, border или shadow
компонента. Повторённый в трёх местах layout становится общим примитивом.

## Визуальный контракт

- Один системный sans-serif для интерфейса; mono — только код, SHA, версии и
  табличные числа.
- Основной текст и secondary text проходят WCAG 2.2 AA `4.5:1`; focus всегда
  видим, motion отключается через `prefers-reduced-motion`.
- Зелёный — бренд и primary action, но не фон всего интерфейса.
- Панели плоские: один border, radius `8px`, максимум одна малая тень.
- Иконка занимает фиксированную колонку `20px`; расстояние до подписи всегда
  `8px`. Навигация и служебные действия выровнены по одному левому краю.
- «Чат», «Студия» и «Конфигурация» — три равные строки одного списка:
  одинаковые width, height, font и icon column. Активность выражает тихий
  зелёный фон и левый индикатор, а не кнопка другого размера.
- Desktop action может быть `34–36px` только в плотной mouse-зоне; основной,
  mobile и icon-only hit target остаётся не меньше `40px`.
- Рабочий экран идёт сверху вниз. Допустимы главный rail приложения и временный
  drawer; постоянная дополнительная боковая колонка контента запрещена.

## Контракт миграции

Перед правкой экрана агент читает `skills/sovushka-ui/SKILL.md`, ищет
существующий примитив и меняет минимальную поверхность. Inline `.style(...)`
не добавляется, если значение относится к визуальной роли. Исторический экран
считается мигрированным только после замены повторяющихся controls/panels,
desktop и mobile smoke, keyboard/focus проверки и записи в `MODULE_INDEX`.

## Текущие поверхности

Windows setup surface использует существующее lifecycle-состояние bootstrap: во время `running`
основное действие disabled и показывает фактическую фазу. До NiceGUI это автономный static
catalogue: LES core, answer providers, embeddings и Qdrant разделены по ролям; Ollama, FreeToken,
Lemonade и OpenAI-compatible получают status и official link, но не install/select action.
Отсутствие внешнего компонента не блокирует основное действие.

Мигрированные поверхности: AppShell/Header, чат, evidence/source cards,
`build_documents(surface=...)`, рабочая и конфигурационная почта, история
диалогов, управление доступом В.О.Л.К. и встроенный Qdrant visualizer. Отдельная
поверхность «Конфигурация → Профили» — один вертикальный рабочий экран для
четырёх режимов «Поиск», «Агент», «Сметчик», «Инженер». Внутри профиля
выбираются versioned промпт и скилл, tool allowlist, температура и RAG policy;
Markdown редактируется bundled CodeMirror и одновременно показывается preview.
Factory Base неизменяема, пользовательские редакции можно создавать с нуля или
копированием и удалять, профильную версию — назначать активной. Новый чат берёт
активную версию, а текущий применяет её только по явной кнопке, поэтому настройка
не меняет середину уже идущего диалога. Legacy редактор системных строк в
«Инструментах» остаётся временным read-compatibility источником для однократной
миграции, но не является каноническим редактором профилей.
Отдельная
рабочая поверхность «Сметный проект» и специальная кнопка «Смета в чате» сняты
в 0.27.77: нормы выбираются как обычный RAG-датасет в общем чате; сохранённые
legacy RIM-сессии не удаляются. Главная
поверхность «Конфигурация → Состояние» и реестр
«Конфигурация → Датасеты», а также операторская проверка ПД/РД по чек-листу
в «Инструментах». В Header
на всех операторских экранах есть постоянный переключатель «Чат · Студия ·
Конфигурация» с иконками, активным состоянием и самостоятельным mobile
контрактом. Эти три первичные поверхности не дублируются в ряду вторичных
вкладок. «Чат» и «Студия» переключают уже построенные панели `/classic`
на месте и обновляют URL через History API; полная перезагрузка страницы для
локального переключения запрещена. «Конфигурация» остаётся отдельной страницей.
Обе тяжёлые страницы создают только запрошенную панель; скрытые документы,
почта, история и административные разделы строятся при первом открытии и затем
создаются через общий `lazy_tab_panels`, а затем удерживаются нативным Quasar
`keep_alive`. Periodic timers чата и Датасетов при этом
деактивируются у скрытой панели и возобновляются только у активной. Датасеты
для live-индикатора читают дешёвый `reindex/status`, а не полный process/service
preflight. Поэтому route entry не ждёт
рендеринга всех неиспользуемых вкладок. Рабочие tab-panel переключаются без
Quasar slide-transition: повторный переход показывает уже удержанную панель
сразу, без искусственной 300-мс задержки. Переход между
разными same-origin маршрутами Чата и Конфигурации использует progressive
enhancement `@view-transition`: короткий interruptible-looking fade/translate
без анимации первой загрузки; неподдерживающий WebView просто выполняет обычный
переход.

В «Конфигурация → Датасеты» локальную папку можно либо выбрать через
loopback-only Проводник/Finder, либо вставить абсолютный путь в то же поле.
Название по умолчанию берётся из имени конечной папки и не перезаписывает
введённое оператором имя. Действие «Открыть файлы» ведёт не в технический
реестр статусов Самовара, а в «Документы / Л.И.С.Т.» с уже выбранным
`dataset_id`. В служебных датасетах загрузка файла представлена компактным
действием; пустой `0.0 B / 0%` uploader не занимает рабочую область.
Desktop UI и встроенный визуализатор слушают loopback `127.0.0.1`, поэтому
обновление Python runtime не вызывает запрос Windows Firewall. Внешний доступ
остаётся отдельной обязанностью P.A.U.K./reverse tunnel.
На desktop общий AppShell использует спокойную классическую структуру
Locia: компактный левый навигационный rail 160 px, вертикальные рабочие разделы и
одну широкую рабочую область. Rail разделён на три читаемые зоны: первичные
поверхности, карточку «Рабочие разделы» и нижнюю служебную область. Все пункты
выровнены влево; статус proxy, обновление, тема, Qdrant, настройки и профиль имеют
подписи, одинаковую высоту и единый ритм вместо набора центрированных иконок.
Заголовок раздела не мельче навигационных подписей, а зоны отделены тихими
surface-shift/ring без тяжёлых рамок. Первичные и вторичные поверхности сохраняют
полные подписи и hover-подсказки: rail не превращается в набор неочевидных иконок.
Мигрированные поверхности
используют единый системный sans-serif с базой 14 px, controls 13 px, согласованными
line-height/весами и моноширинным шрифтом только для кода/чисел. Светлая и тёмная
палитры проверяются тестом на WCAG AA 4.5:1 для основного, вторичного,
warning/error и белого текста зелёных действий; вторичный текст светлой темы
усилен до читаемого нейтрально-зелёного. Палитра переведена с холодного серо-синего на
тёплый нейтральный фон с зелёным акцентом; панели, чат и composer используют
единые тихие границы и малую глубину. На mobile rail возвращается в компактную
верхнюю строку без page-level overflow: в ней остаются бренд и три первичные
поверхности, а вторичные вкладки открываются одной подписанной кнопкой
«Разделы» как текстовое меню вместо ряда нерасшифрованных иконок. Mobile
tab-panel снимает desktop-padding, поэтому чат использует почти всю ширину
viewport. В payload
чата `BLOCKED` выводится отдельно от ответа модели;
`degraded` показывается громко. Источники находятся в одном блоке непосредственно
под ответом: одна строка — одна кликабельная человеческая ссылка
`документ · страница/абзац`. Строка открывает исходник по стабильному `doc_id`,
а для PDF сохраняет точную страницу. Одна вторичная кнопка открывает общий
артефакт «Источники ответа» с теми же ссылками, цитатами и копированием ответа с
источниками; отдельная длинная простыня legacy-фрагментов при наличии `source_map`
не выводится. Raw `source_ref` и служебные типы в первом слое запрещены;
техническая ссылка доступна только в закрытом disclosure карточки источника.
Машинный `error_code` и trace свёрнуты.
Inline-LaTeX без подключённого TeX-рендера нормализуется перед показом: парные
`$...$` не протекают в текст, а escaped currency и display-блоки сохраняются.
Оценка ответа — две подписанные кнопки «Да/Нет» с сохранением через
`/api/chat/history/{id}/feedback`, видимым активным состоянием и повторным
выбором без перезагрузки.

Видимое имя помощника в шапке — **С.О.В.У.Ш.К.А.**:
«Система Обработки и Выдачи: Умная, Шаблонизированная, Классифицированная,
Автоматизированная». Суффикс «· Чат» не выводится: активная кнопка «Чат» уже
однозначно обозначает поверхность и не должна дублировать заголовок. Это
каноническая расшифровка из словаря Л.Е.С.; сокращённая
`С.О.В.А.` не используется, потому что прежняя фраза не соответствовала её
буквам. Имя Python-пакета `sovushka` и переменных окружения не переименовывается,
чтобы визуальная правка не ломала runtime/deploy-контракты. Рядом с именем
используется собственный inline-SVG owl-mark; само имя использует тот же
фирменный зелёный accent, что и Л.Е.С., а расшифровка остаётся нейтральной.
Знак имеет доступное текстовое имя; внешний asset/download не нужен. Логотип **Л.Е.С.** в app-rail
остаётся главным знаком продукта и не изменяется.

`acronym_identity()` задаёт общий контракт фирменных заголовков: акроним сверху
зелёным, каноническая расшифровка снизу нейтральным текстом. Компонент применён
к Л.Е.С., С.О.В.У.Ш.К.А., Д.И.А.Г.Н.О.З., С.А.М.О.В.А.Р., В.О.Л.К.,
П.Р.О.Р.А.Б., Е.Ж.И.К. и Л.И.С.Т. Расшифровки берутся из словаря/канонических
модульных документов. В настройках есть пользовательский switch «Показывать
расшифровки акронимов»: он сохраняется в `app.storage.user`, скрывает только
вторую строку без reload и не удаляет акроним/tooltip. На узкой mobile-шапке
расшифровка Л.Е.С. автоматически скрывается ради полезной ширины.

Верхняя строка чата не является третьей навигацией: документы, артефакты и
новый диалог представлены компактными 40×40 действиями с tooltip/aria, область
поиска остаётся подписанной. Composer имеет явную метку «Ваш запрос»,
контрастное поле и подсказку Enter/Shift+Enter.

В режиме «Смета в чате» каждое terminal-событие `smeta_row` одновременно
обновляет inline-таблицу ответа и один живой черновой Markdown-артефакт в
существующей панели «Артефакты». Строки не дублируются: ключом остаётся
`work_id`; финальный XLSX регистрируется штатным финальным payload. Это только
UI-проекция существующего stream/checkpoint-контракта и не меняет сметное ядро. После финала
потоковая таблица сверяется с авторитетным `rim_trace`: если строка исчерпала модельные ходы и не
успела породить отдельное stream-событие, она всё равно появляется в итоговом артефакте со статусом
«Норма не привязана». Операторский журнал переводит внутренние названия фаз и причины повторной
проверки; защита памяти показывает человеческое русское сообщение без runtime/env-ключей. Та же
полная итоговая таблица восстанавливается при повторном открытии расчёта из истории чата.
При ошибке document workflow backend возвращает `attachment_retry`, router сохраняет это поле,
а composer оставляет тот же server-owned XLSX/PDF для повторного запуска; успешный финал по-прежнему
очищает вложение.

Выбор области/датасета находится только в topbar (`Все источники`); дублирующая
кнопка у composer удалена. Скрепка — отдельная 40×40 outlined icon-button с
едиными radius, optical size, hover и focus-состояниями UI kit.
Диалог области показывает проекты, отдельные источники и базы ЛЕС едиными
карточками: человеческое имя берётся из типизированного registry, технический ID
не занимает первый слой, рядом видны файлы/фрагменты и текущее число выбранных
источников. Пустые системные базы остаются видимыми, но недоступны для выбора.
Обязательный production-реранкер не является пользовательской настройкой:
исторический switch «Реранкер» удалён, а чат не отправляет
`reranker_enabled=false`. Старое поле API принимается только для совместимости
и игнорируется; отключить контур может лишь операторская runtime-политика,
после чего поиск честно возвращает `BLOCKED`.

Документы работают как явная двухшаговая цепочка «датасет → файлы»; выбранные
файлы сохраняются в sticky-действие «Спросить в чате». Почта показывает
последний сбор и состояние индекса, а вопрос из письма переносит exact
`target_file` вместе со scope ящика.

Главная конфигурация устроена как операторский экран, а не как dashboard:
сверху находится единый паспорт готовности с одним зелёным primary action,
ниже — четыре читаемых контура «Доступ и интерфейс», «Поиск и данные»,
«Модели», «Ресурсы Mac/Windows». Диагностика является платформенной:
macOS показывает MLX/Metal и LaunchAgents, Windows — configured answer/embedding provider,
Qdrant и локальные процессы; Mac-названия на Windows запрещены. Статусы представлены строками сервисов, поэтому
название, назначение и результат проверки читаются одним взглядом. Синие
локальные кнопки, отдельные KPI-карточки и тёмная горизонтальная схема не
используются. Детали проверок, резервные копии, словарь и технический журнал
остаются во втором слое через disclosure. Постоянный чёрный terminal-footer
удалён из `/les/classic`: он дублировал журнал и отнимал 120 px рабочей
высоты. Общий буфер событий открывается кнопкой «Журнал» в паспорте. На
390 px паспорт, status strip и контуры переходят в одну колонку без
горизонтального overflow; кнопки сохраняют 40 px hit target.

Под рабочими контурами находится живой паспорт RAG-цепочки. Он использует
общие `panel`, `section_heading`, `status_badge` и `render_feedback_state` и
показывает отдельно: индекс, native RRF, иерархию, RAPTOR, ColBERT,
cross-encoder, parent/context и exact evidence. `Настроен`, `Выключен`,
`Блокирован` и `Готов` не смешиваются: capability-status приходит из
`/api/health`, а фактическое прохождение стадий конкретным запросом остаётся в
его retrieval trace.

RAPTOR и ColBERT управляются здесь же без скрытых переключателей: режим,
модель, бюджеты, fanout/depth, candidate/output limits, локальный summarizer,
timeout и circuit-breaker находятся в GUI-owned policy. Preflight ColBERT не
загружает модель и показывает наличие пакета/кэша, оценку модели и multivector
индекса; неизвестное свободное место Docker честно остаётся блокирующей ручной
проверкой. Кнопки публикации имеют `Danger`-подтверждение, строят отдельную
generation и показывают checkpoint/progress/error code. Poll статуса активен
только пока lazy-вкладка видима.

Самовар отдельно показывает `SKIPPED`, retryable и terminal, стабильный код,
номер попытки и результат последнего bounded auto-repair. `SKIPPED` не
маскируется как ошибка, terminal не обещает автоматический повтор, а repair
никогда не обозначается как полный reindex.

Экран «Датасеты» построен вокруг пользовательского сценария
`найти набор → понять готовность → открыть фактические файлы`. Шесть
равнозначных KPI-карточек заменены одним компактным паспортом корпуса; поиск и
статусные фильтры стоят непосредственно над реестром. Каждая строка использует
один шаблон: фирменная icon-column, имя и тип набора, честный status badge,
фактические числа файлов/индекса/очереди/ошибок/фрагментов, прогресс и две
подписанные операции «Открыть файлы» и «О проекте». Редкие или опасные
действия не конкурируют с основным сценарием: ручная партия, ремонт и удаление
находятся в меню дополнительных действий. Управление очередью, состояние
памяти и параметры партий собраны в один disclosure после списка. На mobile
паспорт, фильтры и строка переходят в одну колонку; page-level horizontal
overflow запрещён. Визуальная миграция не меняет API, содержимое датасетов,
индексы или алгоритм RAG.

«Почта» использует один и тот же operator flow на рабочей и конфигурационной
поверхностях: фирменная идентичность Е.Ж.И.К. → состояние индекса → ящик →
цепочка → письмо → «Спросить в чате». Ящик всегда показывает собственный
датасет, а технические папки и provenance находятся во втором слое. Настройка
не называет конкретный компьютер: Classic Outlook описывается как локальный
ручной read-only сборщик, IMAP — как отдельное подключение. При первом ручном
запуске Outlook-sidecar регистрирует каждый видимый store до обхода писем,
поэтому новый или пустой ящик сразу появляется в Л.Е.С. со своим датасетом.
На 390 px три
рабочие колонки переходят в последовательные секции без горизонтального
overflow.

«История» показывает диалоги как единый читаемый список: название, время,
число сообщений и отдельное действие «Открыть». Загрузка, пустой список и
ошибка используют общий feedback-state; интерактивная строка не содержит
вложенную кликабельную карточку.

«Доступ» В.О.Л.К. использует общий panel/form/list-контракт вместо таблицы:
ключ маскируется, роль и состояние читаются как badges, частые действия
подписаны, а создание ключа использует общие поля и select. На mobile каждая
запись становится одной вертикальной карточкой без горизонтального скролла.

«Визуал» сохраняет граф как специализированный canvas, но его оболочка
использует UI KIT, доступное имя iframe и одно действие открытия. Сам
визуализатор следует общей тёплой светлой палитре: бумажный фон, графитовый
текст, зелёный акцент, видимый focus и reduced-motion; старый чёрно-зелёный
neon-контраст не используется.

«Инструменты» разделены на две задачи: служебные источники и подключённые
системные промпты. Источники используют одну строку с icon-column, статусом,
назначением и компактными действиями; ФГИС имеет отдельный прогресс, а журнал
скрыт disclosure. Prompt registry показывает только реально вызываемые
генераторы: `rag`, `smeta_harness`, `smeta_direct`, `review`, `free`, а также
общий характер и тон. Витринные дубли `auto`, `smeta`, `normcontrol`, `kp`
удалены из редактируемого списка: соответствующие UI-маршруты используют
активный RAG/сметный генератор или детерминированный workflow.

## Границы

Filled КС commands use the same chat backend as the API: a ready download is
registered directly in the Files panel and keeps its `.xlsx` extension. A PDF
attachment in `read` mode is forwarded by `attachment_id` even when local text
extraction is empty, so the document workflow can process it server-side.
No new UI component was introduced for this behavior.

For a smeta draft with unresolved rows or professional conflicts, the artifact
action opens a review dialog with two explicit paths. “Подготовить уточнение”
returns the preserved source attachment and an editable request to the composer;
the model either chooses and exposes a reasonable installation scenario as
`ДОПУЩЕНИЕ`, or asks one question when that choice materially changes applicability,
cost, or cannot be made responsibly. Operator-provided conditions always take
priority. “Принять текущую привязку норм”
is a separate danger action with confirmation. The UI does not select, replace,
or lock norms on behalf of the model or operator.

All operator-facing controls and states use Russian product language. Raw machine
tokens (`unbound`, `mapping`, `lock`, `checkpoint`, `immutable`, `global review`,
`ASSUMED`) are localized at the UI boundary and may remain only inside APIs,
stored traces, source code and technical diagnostics. Proper model/product names
and file-format abbreviations are not rewritten.

- Не добавляет JavaScript/CSS-зависимости.
- Не скрывает `MISSING/BLOCKED` и не создаёт источники.
- Не меняет RAG, выбор модели или права API.
- Полная замена исторического `sovushka/styles.py` выполняется постепенно и не
  является условием одной UI-правки.

## GUI-first конфигурация (0.27.47)

В Д.И.А.Г.Н.О.З. доступны два операторских контура: политика RAPTOR/ColBERT и полный реестр runtime/env-факторов. Реестр всегда показывает ключ, источник effective-value, необходимость перезапуска и mutability; секретное значение никогда не возвращается клиенту. Опасные параметры имеют метку `Danger`, требуют отдельного подтверждения и перед записью создают recoverable backup. Bootstrap-пути видны read-only. Optional RAG-стадии получают режим только из persisted GUI-политики; env не может скрыто включить или выключить их.

FreeToken показывает токенное окно и соответствующий лимит prompt рядом. При изменении окна
Совушка пересчитывает безопасный символьный бюджет с резервом генерации; после пересчёта оператор
может явно скорректировать лимит. Effective value API и значение поля используют одну функцию,
поэтому скрытого расхождения GUI↔runtime нет.
