# RAG evidence flow

## 965 — составной исходник без предметного объединения

POST `/api/chat/attachment-collections` принимает упорядоченные уникальные IDs
уже загруженных read-вложений. Сервис копирует их точные байты в собственный
ZIP_STORED-контейнер `.lescollection` с каноническим манифестом. Это внутренний
формат транспорта; произвольный ZIP/JSON пользователя им не считается. Входные
данные не исполняются, пути entries задаёт сервер. Контейнер и metadata связаны
SHA, проверяется каждый член, размер, состав и отсутствие повторных ключей.
Суммарные байты ограничены прежним upload limit; фиксированного числа файлов нет.

Parent ID/SHA используются прежним заданием, checkpoint и цепочкой ревизий.
После удаления временных child uploads комплект читается из собственных байтов.
Успешно прочитанный через server attachment ID typed-источник получает проверенный
по SHA retention marker. После этого TTL и one-shot consume его не удаляют;
неиспользованные загрузки живут по прежнему TTL. Pin повторно проверяет hash/size
без удаления источника, пересёкшего возрастной порог во время извлечения. Уже
удалённые старые источники этим механизмом не восстанавливаются. Фактор срока
временных загрузок показывает actual default604800 и обязательный restart в GUI.
Прежние PDF/DOCX/XLSX/CSV/RTF adapters дают union catalog: адрес и технический ID
получают namespace члена, значения/cells/формулы и исходные offsets сохраняются.
Манифест содержит имена/SHA/статусы, side index — original locator/file provenance.
Сортировка разных файлов не использует их несопоставимые локальные offsets.
Непрочитанный член явно остаётся в комплекте, extraction_complete=false;
прочитанные строки соседних файлов не выдают за полноту всего исходника.

Source frame сохраняет полный immutable audit и все адреса. Model render
показывает literal origins только фактически показанных строк, с количеством
непоказанных и указанием `read_source` для доступа; весь member manifest остаётся.
Native reader возвращает исходный адрес и имя конкретного файла вместе с parent
identity. VOR/LSR packager получает этот же доверенный каталог через private
server-only аргумент. Публичные model arguments этот аргумент не допускают.
Работы, нормы, связи ресурсов и применимость остаются решениями модели.

Правило формата документа объединено с прежней подсказкой навигации в более
короткий текст. Сохранённые profile prompts не изменяются; input/output/wire
лимиты и literal evidence не увеличиваются и не вырезаются ради вместимости.
Подпись native чтения нейтральная: «чтение источников», также при сборке ВОР.
Регрессии965 scoped; installed multi-file, B0/B1 и большой ВОР ещё pending.

## 964 — named-text carrier без потери кавычек и неполных работ

В явном model-authored поле полная JSON-строка читается как её строковое
значение; исходный ответ сохраняется. Это относится также к plain label
`artifact_kind: "vor"`. Не JSON-строка, неполное значение, конфликт или повтор
декларации не получают догадку/приоритет. Прежний block reader сохраняет
one-to-many source rows и ID/revision; duplicate fields остаются raw proposals.
Explicit unquoted `null` в nullable поле означает отсутствие, quoted"null"
остаётся строкой. Неизвестная норма не удаляет явную работу ЛСР.

Общие подсказки человеческого Markdown/без JSON относятся к обычному ответу;
для создаваемого документа действует его контракт строк. Сохранённый prompt
профиля не изменяется. Нового model round, selector или YAML-executor нет.

## 963 — сохранение запросов и обоих вариантов результата

Model-generated declare_research_queries_result внутри точного schema/kind/data
wrapper передаётся общему reader как непроверенный model envelope. Сами queries,
тип и commentary не меняются, runtime-факты из него не принимаются. Первая
упаковка/база цен и итоговый admission по-прежнему принадлежат существующему
серверному контексту. Два envelope, неизвестные/предметные поля и конфликт
не устраняются выбором одного варианта.
Missing query type сохраняет оба разрешённых профилем optional terminal:
фактический единственный вызов модели объявляет тип. Unknown использует две
компактные технические схемы без дублирующей текстовой подсказки; полный
explicit-VOR контракт не меняется. Условный ВОР сохраняет правила работ,
родительских связей, исходных единиц и обоснования объёмов. Чтение без документа
и обычные форматы сохраняются. Exact anchors/ID, авторские extra fields и
последующие проверки не урезаются ради вместимости.
Нового inference/research/review цикла эта правка не добавляет.

## 962 — optional terminal ВОР/ЛСР и сохранённые финансовые вопросы

Canonical native build_vor_workbook требует decisions; отсутствие набора не
означает разрешения переписать спецификацию. Явный пустой набор сохраняется
только как промежуточный файл с MODEL_WORK_ROWS_EMPTY. Отдельный literal terminal
adapter не исполняет инструмент: model rows должны пройти прежние admission,
durable merge и packaging. Он не выбирает и не исправляет работы, количества,
нормы или parent links. Смешанные native/read calls и два конфликтующих видимых
результата — техническая неоднозначность, а не повод выбрать одну версию.
Optional terminal в evidence-read driver завершает тот же модельный ход без
нового обращения к модели. Обычный текст сохраняет прежний путь.
Та же граница принимает model-declared ЛСР через существующий build_lsr_workbook.
Native schema предлагает только attachment_id и decisions, требует technical
identity при прежних операциях и условные поля выбранной нормы; это подсказка
формата, а не доказательство constrained decoding или правильности выбора.
Provider finish/raw arguments сохраняются отдельно от semantic carrier finish.
Исходная задача, полное доступное evidence и обычные форматы ответа сохраняются.

Schema использует весь буквальный каталог, а не только текущий frame.
Принятые факты read_source позволяют сохранить новые авторские строки вне
текущего кадра при том же source SHA/file ID; неизвестные адреса, закрытые
операции и строки вне explicit review остаются защищены.

Явное resource_review.separate_supply_reviews не изменяет ресурсы нормы:
модель определяет отношение поставки к ним и цитирует прочитанный состав.
Ссылки сохраняются как immutable bindings, конфликтующие/непрочитанные
основания не снимают overlap. Финансовые незакрытые операции входят в retry
вместе с пробелами норм. Snapshot фактического расчёта сохраняется в событии
упаковки и передаётся лишь в запрошенный preserving review/retry при равенстве
accepted row revision/hash, source scope и pricebook SHA. Новый расчёт или
профессиональное решение вместо модели при этом не выполняется.
Интеграция и установленный comparative gate962 ещё выполняются.

## 960 — текущий источник не завершает native thinking-ход

При непустом строковом `reasoning_content` в типизированной native-цепочке текущего
пользовательского хода CURRENT_READ_FRAME передаётся перед этой цепочкой. Иначе
Qwen template трактовал добавленный после tool-result user frame как новую
человеческую реплику и отбрасывал прежний reasoning. Canonical transport fields
при этом были сохранены: дефект находился в порядке сериализации, а не в тексте.
Измерение установленного tokenizer/count endpoint: reasoning marker добавляет
354 токена перед цепочкой и 0 после неё; это измерение входа, не доказательство
качества профессионального выбора.

Required boundary cue называет frame текущим source/evidence, native exchanges —
завершёнными чтениями этого же хода, а источник — untrusted evidence. Cue виден
в trace и входит в whole-wire budget. Source rows, evidence refs/cards, native IDs,
аргументы, model reasoning и professional decisions не переписываются.
Initial/query, native reads с None/пустым/пробельным reasoning и terminal tools-off
сохраняют прежний порядок. Не вводится глобальное сохранение исторического thinking,
новый model-specific switch или новый предметный цикл.

Регрессия: `test_native_reasoning_frame_960.py`; обязательны live B0/B1 на одной
модели, области и источнике. Профессиональная готовность отдельно от transport.

## 959 — необязательный native-перенос поискового конверта

На двух существующих query-callsite `model_query_declaration_transport_service`
проверяет действующий снимок TOOLS назначенного подключения через прежний
`require_capabilities`. При поддержке предлагается одна необязательная функция
`declare_research_queries`: те же `queries`, необязательные `artifact_kind` и
`commentary`. Это канал передачи прежнего результата, не выполнение поиска и
не дополнительный агентный цикл. Содержимое запроса и выбор документа принадлежат
модели; `tool_choice`/`response_format` не навязываются.

Схема проходит тот же ContextGovernor. Только overflow обязательного кадра со
схемой вызывает до отправки точный прежний текстовый fallback, без её добавки и
без удаления исходника/evidence. Если и он не помещается, вызова модели нет.
UNKNOWN/UNSUPPORTED, слабое или просроченное evidence сохраняет прежний текстовый
путь; новый probe не выполняется. Выбранный канал, причина и scope снимка видны
в trace. Один распознанный вызов передаёт raw arguments прежнему
`read_model_query_response`; видимый сопроводительный текст сохраняется.
Неверные/multiple/unknown calls не становятся поисковыми строками: сохраняются
в диагностике прежнего ограниченного repair/pending. Ответы, карточки, выбор
операций/норм/ресурсов и XLSX не переписываются.

Регрессии используют actual B0/B1 application/governor boundaries, включая
`finish_reason=tool_calls`; они не доказывают живое качество модели или ускорение.

Nonstream-ответ хранит только размеры исходного content/reasoning и итогового
текста, а также reported `reasoning_tokens`, если провайдер его сообщил.
Счётчики проходят оба прежних usage-whitelist. Текст reasoning не публикуется;
неизвестный канал не считается пустым. Это позволяет различать отсутствие
финального текста и неизвестную структуру без догадок о причинах `length`.
Stream/native protocol и финальный текст не меняются.
Регрессия: `test_model_output_observability_959.py`.

`project_final_artifact_carriers` сохраняет выпущенный workbook с непустым
`revision_id` основным артефактом final, как в history и durable document.
Навигационные реестр и блокнот доступны отдельно; они не затирают файл.
Если workbook не выпущен, прежний приоритет навигационных блоков сохраняется.
Dangling metadata без revision не считается выпущенным файлом.
Регрессия: `test_workbook_primary_artifact_959.py`.

## 958 — идентичность операции при сохраняемом пересмотре

На адресе уже выбранной для пересмотра операции ответ без `operation_id`
не объявляет новую работу: он сохраняется в unapplied proposals с причиной
`missing_operation_identity`. Baseline и pending-очередь остаются доступными.
Существующая операция возвращается с её ID и expected_revision; новая операция
на том же адресе явно объявляется пустым строковым ID. Это одинаково работает
для JSON, Markdown и построчного формата. Код не угадывает соответствие по
названию, роли, норме или объёму. Новые адреса без baseline не ограничиваются.
Технические алиасы ID/локатора нормализуются так же, как в admission/merge:
они не позволяют изменить закрытую соседнюю операцию вне точной области добора.
Текст решения и отвергнутые предложения не переписываются. Контекст прежнего
результата явно описывает ID и expected_revision, дополнительных вызовов нет.
Эквивалентные адреса также согласованы в scheduler, prior context и завершении
pending: допущенный ответ закрывает именно свою попытку, сохраняя исходный текст.

`latest()` фильтрует точные session/attachment в SQL до ORDER/LIMIT, читает
только ID/identity совпавших кандидатов, затем полный снимок одного найденного
задания и его события. Более200 новых чужих заданий больше не скрывают старую
сессию. Порядок и AND обоих ID сохранены; параметр limit ограничивает совпавшую
выборку. Тяжёлые evidence/query-cache чужих заданий для поиска не читаются.

## 957 — cooperative stop существующего model call

`await_workbook_model_call` ждёт тот же неизменный transport call параллельно
с узкой durable проверкой `run_should_stop` по ID текущего задания. Stop отменяет
его Task и ждёт освобождения ресурсов; транспортная ошибка не скрывается и
авторетрай не запускается. Готовый ответ имеет приоритет над одновременной
остановкой; следующая попытка проверяет stop до dispatch. Packet deferral не
прерывает другое исследование. Существующий outer CancelledError-path сохраняет
baseline/evidence, упаковывает допустимый частичный файл и освобождает job gate.
Скорость остановки генерации на стороне внешнего сервера зависит от поддержки
разрыва соединения; глобальный сервер приложения не останавливает.

## 956 — scope native read-инструкций

`model_evidence_read_instruction` получает artifact_kind из текущей декларации
модели. Явный vor получает инструкцию чтения точных исходных строк и выбранных
документов, без обязательного расчёта норм/цен/НР/СП; добровольная норма требует
основания карточкой. Lsr и неизвестный тип сохраняют прежний полный контракт.
Начальный pre-query scope неизвестен; packet и direct scope берётся из той же
artifact_kind_declaration. Набор read-tools, исходные и retrieved evidence не
фильтруются и не заменяются. Дополнительный модельный цикл не добавляется.
ВОР описывает включённые операции через covered_by_work_id и coverage; это
решение модели, не автоматический выбор parent work приложением.

## 955 — повторное исследование без потери первой ревизии

`accepted_work_index` в обычном prior-page context — компактный индекс всех
сохранённых работ других пакетов того же документа. Восемь колонок передают
дословные ID, ревизию, source_row, название, единицу, объём, шифр и статус.
Он доступен и при пустом current-packet baseline; оба существующих callsite
передают его следующим query/reader/answer. Индекс не является новой карточкой
нормы, не выбирает родителя и не открывает закрытые работы для нового поиска.
Контроль318 работ без пропусков выполнен для окна131072; меньшие окна этим
опытом не квалифицированы. Подробные карточки не дублируются.

`model_rag_prior_page_context` показывает `applicability_fields` для выбранной
нормы: исходные пять признаков и их буквальное чтение кодом, допустимые значения
и поле пояснения coverage. Проза не подтверждается как yes; предметное решение
не меняется и дополнительный модельный цикл не запускается.

Назначение: после частичного результата добрать нормы или учесть замечание
инженера, сохранив уже принятые операции и возможность продолжения после обрыва.

- `reopen_locators(..., preserve_accepted=True, operation_ids=...)` сохраняет весь
  accepted baseline, evidence, query cache и подтверждения инженера. Явный список
  ID ограничивает пересмотр операций общего исходного адреса; `None` предлагает
  все прежние операции указанных адресов. Пустой список сохраняет адрес как
  область для нового ответа, в том числе при существующей строке материала.
- Область хранится в `task_context.pending_research_operation_ids`,
  `pending_research_locators` и `pending_research_unassigned_locators`, а не только
  в событии. Новый job того же документа наследует её вместе с исходной задачей,
  выбранной региональной книгой и её hash. Цепочка документов читается прежним
  `document_packaging_events`; собственное `job.document` относится к его упаковке.
- `record_packet` снимает ожидание существующего ID только после admission
  модельного ответа по тому же исходному адресу. Принятое подтверждение неизменной
  операции достаточно для завершения этой попытки; неизвестный ID, stale revision,
  отвергнутая строка, пропуск ответа и повтор старого материала его не заменяют.
  Исходный `CONFLICT` не превращается кодом в `MISSING`. Новый ответ может
  по-прежнему содержать профессиональный пробел, видимый в следующей ревизии.
- `research_settled_source_keys` исключает pending-адреса из технически закрытой
  очереди, `model_rag_research_target_context` обозначает целевые ID, остальные
  решения служат сохранённым контекстом. `pause` не стирает ожидания; stale
  `finish(complete)` оставляет `paused/research_pending` и квитанцию отказа.

Readiness возвращает `research_locators/research_operation_ids` и действие добора
для частичного завершённого прохода даже при `remaining=[]`. GUI передаёт эту
область в `/api/chat/patch-lsr-rows` с `preserve_accepted=True`; обработчик
проверяет session, attachment и running-state. Обычное замечание в чате также
использует сохраняемый пересмотр. Дополнительного автоматического предметного
цикла нет: нормы, работы, объёмы и цены выбираются прежней моделью.

Legacy-вызов `preserve_accepted=False` сохраняет прежний destructive-контракт
только вне активного pending-адреса; смешение с сохраняемым пересмотром отклоняется
до мутации. Тесты: `test_workbook_gap_followup_955`,

## Назначение

Обычный чат и model-authored estimate используют один принцип: модель сама формулирует запросы и
пишет итог, код только выполняет retrieval, сохраняет provenance и механически исполняет
разрешённый постпроцессинг. На сметном пути к запросам модели добавляется гарантированный системный
сбор кандидатов (ADR-16, см. ниже); он не отнимает у модели ни выбора нормы, ни решения о
применимости. Дополнительного planner/model-review шага и JSON-протокола между моделью и RAG нет.

## Активный поток

Необязательное рассуждение модели задаётся строгим boolean
`model_policy.reasoning_enabled` в сохраняемой пользовательской версии профиля;
отсутствующее поле означает `false`. Переключатель «Рассуждение модели» находится
в существующем редакторе профилей, requested/effective/source видны в диагностике
исполнения, перезапуск не требуется. Политика проходит через bound runner и
typed `InferenceRequest` одинаково для B0/B1 и продолжений чтения; FreeToken
получает `chat_template_kwargs.enable_thinking`. Модель, провайдер, sampling,
KV и резерв контекста не меняются. Для generic OpenAI-compatible подключения без известного управления transport
сохраняет `requested=true`, но показывает `effective=false` с причиной
`unsupported_by_transport`; поддержка не угадывается. Известные способы —
FreeToken template flag и уже выбранный native Ollama protocol.
Отдельные reasoning-каналы и ведущий `<think>`-блок,
включая разрезанные streaming tags, не передаются parser строк; после начала
финального текста буквальные XML/code markers сохраняются. Ответ без final
content при исчерпании генерации остаётся видимой технической остановкой без
выдуманных строк и дополнительного предметного вызова. Это опция для проверяемого
эксперимента; улучшение качества требует установленного live-сравнения.

С 861 query-output ограничен фактическим `query_packet.generation_reserve_tokens`.
Пустой GUI-фактор `LES_CHAT_MODEL_RAG_QUERY_MAX_TOKENS` означает auto: до 1600
без рассуждения, при явно включённом рассуждении — уже выделенный резерв.
Явный положительный cap также ограничен резервом; ошибка настройки видна отдельно.
Каждый call сохраняет safe `model_query_outputs` (requested/effective/source,
reserve, finish, usage, final_chars) без hidden reasoning и текста источника.

candidate checkpoint остаётся paused и resumable без workbook. Завершённый
невалидный final по-прежнему допускает штатный repair; законченные строки
обрезанного query list сохраняются, оборванная последняя не исполняется.

   исходная Q/H группа сохраняет место, score и ссылку на это тело.
   Manifest хранит фактически показанное тело по каждому immutable ID,
   ссылки на разные источники не объединяются. Аналогично сокращаются
   повторы уже процитированных тел в контексте следующей страницы.
   С 845 prior_model_decisions сохраняет авторские поля, IDs и все citations,
   но не повторяет application-derived _quality_gate/_evidence_check/
   quality_message. Эти диагностики остаются в durable state и GUI; их
   повторные дампы не вытесняют очередную целую evidence-группу. Тела
   процитированных карточек не сокращаются этим изменением.
   После durable record_packet приложение возвращает назначенные им
   operation_id модели: прежняя операция может быть авторски пересмотрена
   как revision N+1; новая остаётся без ID до записи. Неизвестный ID или
   перенос существующего ID на другую source_row — структурная ошибка.
   Код не угадывает, какие разные операции надо объединить. Прогресс
   показывает доставленные группы карточек отдельно от числа source rows.
   Транспорт принимает обычные строки. Кавычки и явно написанная самой моделью
   оболочка `search_sources("…")` снимаются только синтаксически; вступительная
   проза при наличии таких строк не превращается в дополнительный запрос.
   Пакетный sheet-pass — тот же порядок, что у малого исходника: модель
   формулирует запросы, получает источники, принимает решения, код считает.
   Порог «маленький/большой документ» не выбирает другой контур. Первое
   принятое решение модели по строке сохраняется, обязательный verifier
   и кодовые заглушки при исчерпании попыток не запускаются. Кэш запросов и
   незакрытые locators живут в `workbook_research_jobs`; повтор поиска
   обработанного не выполняется, повтор упаковки XLSX — без модели.
   Оператор может уточнить выбранные locator или внести подтверждённые
   данные (`conversion_factor`/`conversion_source`) без смены шифра.
   Упаковка XLSX принимает то же `confirmed_data` в контракте
   `build_lsr_workbook`; поле доходит до расчёта, а не отвергается schema.
4. Фактически показанные модели chunks образуют immutable evidence manifest.

## Необязательные чтения в answer-ходе (candidate 859)

Модель получает native read-only schemas и может запросить недостающее evidence
до итоговых строк: `read_norm_card`, `search_pricebook_resources`,
`read_resource_price`, `search_sources` (`target=norms|documents`), `read_source`.
Если она сразу вернула итог, новых model calls нет. B0_DIRECT получает те же
доступные действия; original/derived candidate queries остаются вне baseline.

Exact norm reader допускает только ранее показанный pointer: key/code conflict
не выбирает альтернативу. Карточка содержит все resources, per_unit/units,
work steps, provenance и явные count/completeness/consumption flags. Unknown
расход не выдаётся за полный ресурсный состав. Поиск документов использует
замороженные selected datasets; цена читается из закреплённой region/quarter
книги. Model-selected resource и условие НР/СП остаются выбором модели.
`fgis_price_service.get_pricebook` использует официальный reader и cache
snapshot по whole-file SHA-256/размеру; замена bytes по тому же path/mtime
не возвращает старую книгу. Typed price body, metadata и source_ref сохраняют
exact hash/name/size. Drift при чтении или mismatch с сохранённым task hash
возвращает conflict; partial snapshot не объявляется доказательством цены.
Фактический hash сохраняется в packaging `price_basis` и document/job projection.
Continuation той же literal книги проверяет expected hash до расчёта/render;
замена bytes даёт `PRICEBOOK_VERSION_CONFLICT` без нового artifact. Reader
не архивирует прежний файл; legacy basis без hash не доказывает прошлую версию.

`run_model_evidence_read_turn` исполняет literal calls, различает все аргументы
и останавливает повтор одного вызова; полный read result привязывается к новым
immutable Q/H evidence IDs и сохраняется до продолжения модели.
`shown_evidence_registry` передаёт literal предыдущие тела со всеми aliases;
точные norm pointer/source/edition с идентичным либо проверенным prefix view
разделяют одно уже показанное тело. Разные документы/price evidence с разными
IDs остаются отдельными. Shared-body reference разрешается только в фактический
показанный original; отсутствующее или неоднозначное тело явно unavailable.
ContextGovernor сохраняет целые обязательные source/evidence объекты и
учитывает schemas; overflow — видимая technical capacity pause. Read receipts
и exact cards durable, но сами по себе не отмечают source rows выполненными.
С 868 `compact_read_replay` повторяет полные показанные тела с exact shared
catalogs; deferred entries сохраняет как буквальные компактные identity pointers,
не раскрывая непоказанное stored body. Повторные projections aliases/IDs/delivery
flags не раздувают inventory в обязательный JSON registry. Source SHA/edition
разделяют разные карточки; original attachment, question и model decisions остаются.
До первоначальной выдачи групп B0/B1 одинаково оставляют native growth reserve:
`min(answer generation reserve, available group tokens / 2)`, с уменьшением до
остатка после первой целой группы. Уже помещавшаяся первая группа сохраняется;
inventory tail имеет explicit cursor. Requested/effective reserve и источник
расчёта видны в `native_read_growth_budget` trace, новых runtime factors нет.
Три чтения при call budget=3 ещё допускают terminal model continuation;
новое четвёртое чтение получает `evidence_read_budget`. Фактически слишком
большие полные результаты дают честную capacity pause, без обрезки тела или
подмены профессионального решения.

`model_lsr_result_contract` — общий контракт таблицы, JSON и подписанного текста:
выбранная work-норма требует пять match flags и coverage, выбранный supply
resource — resource_code/refs, выбранное условие НР/СП — известный rule ID либо
конкретный вопрос. Delta не требует повторить уже сохранённые операции.
`model_result_packet_service` допускает только текущую packet identity либо
явно предложенный известный operation_id; source/revision conflicts и новые
внепакетные строки остаются полными unapplied proposals. Это структурная
принадлежность пакету, не исправление роли, объёма или нормы.

Supply price/unit/source и optional quote context проверяются по фактически
процитированным телам. Один resource_code или model token `price_source=operator`
не создаёт подтверждения. Неподтверждённая цена сохраняется как preliminary/gap;
её наличие не разрешает ложную confirmed sum. Source quantity errors одинаково
проверяются для work, material и equipment до расчёта.

Source catalog не обрезает клетки до 480 символов, сохраняет 0/False и пустые
колонки. PDF catalog использует conversion без preview character cap; это не
гарантия распознавания произвольного скана. ВОР из authored decisions принимает
PDF/XLSX/XLSM/DOCX/CSV; это поддержка source reader, а не обход upload policy.
XLSM входит в default `RAG_UPLOAD_SUFFIXES` и picker без исполнения macros;
явный operator override сохраняется. Actual saved 870/871-control override
не содержит `.xlsm`, поэтому такой upload не разрешён текущей политикой.
DOCX сохраняет literal body/table/header/footer locators,
unread images/textboxes/embedded content отмечаются source_extraction_incomplete.
Примечания другого листа видны как reference_only_source_rows и не расширяют
requested_source_rows. RTF/ZIP не поддержаны этим workbook-путём; пустой ВОР
получает NO_SOURCE_ROWS до создания файла.

## Происхождение поисковых запросов (ADR-16)

Каждая исполненная поисковая группа несёт `query_provenance` — в заголовке группы и в trace:

- `model` — запрос, написанный моделью; его заголовок `[Поисковый запрос Qx] …` остаётся
  байт-в-байт прежним;
- `original` — дословный исходный текст строки каталога без сокращений и пересказа, с меткой
  «дословный исходный текст строки»;
- `derived` — тот же дословный текст плюс только явно представленные в исходнике атрибуты
  (заголовок раздела листа и написанный в ячейке шифр), с меткой «системный подбор по атрибутам
  этой строки».

Авторы `original`/`derived` — `proxy/services/lsr_candidate_query_service.py`, единственное место
активного сметного пути, где запрос пишет код. Системные группы добавляются к группам модели после
того, как её запросы исполнены, идут в тот же read-only `search_sources`, в ту же
contract-versioned named `dense + bm25_sparse` коллекцию, native RRF, общий rerank и тот же кэш
запросов: параллельного поиска, отдельного индекса и case-specific boost'ов нет. Точно совпавший с
уже исполненным запрос не дублируется, близкая формулировка остаётся — сводить разные запросы в
«один и тот же» код права не имеет.

Scope: только профиль `estimator` на табличном sheet-pass (`mode == estimator` в effective
snapshot) и явно объявленный моделью текущий `artifact_kind=lsr` со статусом `declared`.
**Кандидат 950:** отсутствие типа в запросном ходе не означает ЛСР и не разрешает
системные `original`/`derived` группы. Это относится и к новому естественному замечанию
к ранее собранной ВОР: сохранённый тип не превращается в сметный default и не заставляет
модель сохранять его, если теперь заказана ЛСР. Все буквальные запросы самой модели
исполняются до этой проверки без изменения; новая явная декларация `lsr` допускает
сметные добавки штатным путём. На обычном пользовательском dataset/chat-прогоне и в quality-diagnostic-раунде
происхождение проставляется явно как `model`, и системных запросов нет вовсе; сравнительный baseline
`B0_DIRECT` их не исполняет, а trace честно пишет `system_candidate_queries.status = skipped_baseline`.
Сбой retrieval на системном запросе виден как `search_blocked` и не превращает строки в `MISSING`.

**Кандидат951:** первый и исправляющий query-вызовы через
`govern_model_query_messages` получают в копии обязательного request
`current_phase=search_queries` и краткий `technical_request`. Это техническое
обозначение текущего этапа рядом с неизменённым вопросом пользователя, а не новая
предметная задача. Профиль, все допущенные исходные объекты, число вызовов и
буквальные запросы сохраняются. Весь request учитывается ContextGovernor;
невместившийся обязательный объект остаётся ошибкой, а не усечением. Конечные
вызовы не получают этот этап. Регрессия: `test_model_query_phase_request_951.py`.
Гипотеза вызвана живыми ответами949, выдавшими конечную ВОР вместо запросов;
её эффективность требует отдельного установленного контроля.

**Кандидат953:** одинаковые декларации отдельных конечных пакетов уже
объединяются `merge_model_artifact_kind`; повторно декодировать их склеенный
текст как один ответ нельзя. Отдельный живой отказ вызвала redundant plain+JSON
пара внутри одного ответа. `decode_model_artifact_kind` принимает только один
top-level plain label и один полный JSON-документ с одним ключом artifact_kind,
если значения совпадают и равны vor/lsr. Повтор ключа, два JSON или два label,
разные типы и неполный JSON по-прежнему отклоняются; авторский текст не меняется.
Это узкая совместимость уже поддерживаемых транспортов, не угадывание назначения.

При запрошенном пользователем пересмотре `model_rag_prior_page_context` передаёт
компактные факты существующего структурного аудита предыдущего результата рядом
с `source_comparison`. Аудит видит весь прежний граф; показываются вопросы текущих
source_row. Валидная ссылка в другой пакет не объявляется отсутствующей.
Код не исправляет роли/связи/объёмы, не выбирает нормы и не запускает новый цикл.
Тип прежней ревизии фиксируется в prior_artifact_kind существующей chat-review
event-note и возвращается через chat_review_context после resume. Он не задаёт
тип нового ответа: модель может перейти от ВОР к ЛСР, сохранив факты прежней проверки.

Compact replay сохраняет авторское `calc_unit` рядом с calc_quantity и основанием
расчёта. Пропуск единицы в прежнем whitelist не означает отсутствия поля у модели;
в953 повторный показ не теряет его и не выводит другую единицу кодом.

Если до итогового ответа модель ещё не объявила тип документа, вопрос содержит два
**условных** контракта: компактный ВОР применяется только при `artifact_kind=vor`, ЛСР —
только при `artifact_kind=lsr`. Выбор остаётся за моделью по запросу пользователя и исходнику;
поиск норм и расценка не становятся требованиями готовности ВОР. В system-сообщении этого
`workbook_result` остаются общие роли исходника и правило выбора, без повторного полного
контракта и без безусловной сметной инструкции. Явные контракты `vor` и `lsr` сохранены;
обязательный вопрос с обоими условными контрактами проходит тот же ContextGovernor целиком.
Полный специальный контракт ВОР подаётся при явной декларации `vor`, без его дублирования
в ещё не определённом ходе: проверенные capacity-границы не расширяются ради prompt.
Регрессии: `test_vor_candidate_scope_950.py` проверяет реальное сохранение ВОР → замечание,
буквальные модельные запросы, отсутствие добавок без нового типа, разрешённый переход
ВОР → ЛСР, неизменность B0 и байтовую идентичность явного контракта ЛСР.

Grounding: каждый нетривиальный токен запроса обязан дословно встречаться в его собственных
строках-источниках; при нарушении запрос отбрасывается целиком и остаётся видимым в
`dropped_ungrounded` с `reason = query_token_not_in_source` — не «исправляется». Технологию, условия
производства, объём, применимость нормы, коэффициенты и профессиональный статус код из текста не
выводит и норму не выбирает.

Факторы (категория `smeta`, видны в Совушке, применяются со следующего запроса без рестарта):
`LES_LSR_SYSTEM_CANDIDATE_QUERIES` — default `on`, выключенный возвращает путь «только запросы
модели»; `LES_LSR_SYSTEM_CANDIDATE_MAX` — default `24`, технический предел числа кодовых запросов
на пакет строк: по достижении предела код не добавляет запросов к оставшимся строкам, и это не
признак отсутствия нормы; `LES_LSR_SYSTEM_CANDIDATE_MAX_CHARS` — default `12000`, символовный
бюджет текстов кодовых запросов на пакет: перешедший бюджет откладывается в
`deferred_by_char_budget`, а не вытесняет соседей по пакету.

## Объявленные запросы: prompt, reader и адаптер (блокер § 2, 29.09)

Формат списка поисковых запросов объявлен один раз — `_DECLARED_QUERY_MARKER_EXAMPLES` и
`_MODEL_RAG_QUERY_FORMAT_CONTRACT` в `proxy/services/chat_evidence_application_service.py` — и
цитируется и prompt'ом sheet-pass, и prompt' ordinary-пути, и читается тем же reader'ом
(`read_declared_query_list`). `is_model_rag_search_query_line` и `classify_model_rag_query_lines`
делегируют ему, поэтому второй разбор одной строки не существует. Обычный текстовый вывод,
нумерованный (`1.` `1)` `(1)` `1-` `№ 1:`) и маркированный (`-` `*` `•` `—`) список читаются как
запросы; со снятием маркера снимается только оформление, формулировка остаётся дословной, а «2.5
мм2 кабель» не режется на «номер списка».

Сопровождающий ответ (вступление, пояснение, заключение, `|---|---|`, заголовок, подпись без
запроса) отделяется по структурному правилу и сохраняется с причиной в
`declared_query_rejections.reasons`; он не исполняется и не выбрасывается. Русские префиксы из
исторического списка заморожены и не пополняются: незнакомая формулировка прозы классифицируется
по форме, а не по совпадению со словарём.

Адрес строки запрос получает из самого ответа модели: написанный локатор печатается в заголовке
группи (`[Поисковый запрос Q3] … [строки: СКС!R12]`) и входит в бюджет символов той же функцией;
совпадение с текстом строки пакета (`literal_matches_row`) остаётся в trace и в заголовок не
пишется, потому что решение «о каком строке этот запрос» не кода. Локатор вне пакета сохраняется
как `address_outside_packet` и не переписывается. Кодовые кандидаты печатаются со своим локатором,
а дословный текст строки для обоих случаев читается одной функцией `row_literal_text`.

Системный запрос строится из релевантного исходного текста и явных характеристик: служебные
колонки (итог, стоимость, сумма, цена, всего, П/П, эксплуатационные расходы) и ячейки-ссылки формул
из текста строки исключены, подписанный столбец берётся из `CatalogRow.column_headers` — тех же
заголовков, которыми `attachment_source_catalog_service` размечает `line`; голое число получает
подпись своего заголовка только на `derived`. Строка без проверенных метаданных ячеек сохраняется
своим `line` целиком, и об этом пишет `source_text_filter`. Значимые размеры, состав и условия при
этом не удаляются: исключаются только перечисленные по имени служебные колонки.

Всё вышеперечисленное держится на одном предусловии: каталог должен посчитать строку заголовков
`header`. В 826 фильтр и `derived` были написаны, но на клиентском ВОР не сработали ни разу,
потому что ни одна строка заголовков туда не попала: шапка каждого листа называет денежные колонки
(«Материал (итого), руб. без НДС», «Стоимость (итого), руб. без НДС»), то есть содержит слово
подытога, а деньги там формулами, которые не дают вычисленного числа; правило подытога брало такую
строку себе, и дальше `column_headers = ()`, `quantity_column_known = False`, `header_quantity = None`
оказывались на всех 439 строках. Разрешение — порядок и форма, а не список слов: сначала
`_looks_like_column_header_strip` (≥2 непустых ячеек и ни одной ячейки-выражения) вместе с маркером
заголовка, затем подытог. Настоящая строка итога так и остаётся `subtotal` — она либо несёт число,
либо состоит из формул; на клиентском ВОР все 19 таких строк (`АР!R109`, `АР!R111`, …) сохранили
класс. Проверено пробой на боевом загрузчике (`stage_b/b2_header_probe_827.py`;
`stage_b/live_826/header_probe_before_groups.txt` против
`stage_b/live_827/header_probe_after_fix.txt`): 10 шапок связались, на реальных пакетах по 10 строк
системные запросы перестали терять служебные колонки (0 → 384 из 641 ячеек), группа `derived`
появилась (0 → 79), количество работы перестало путаться с номером позиции.

Измерение разделено: `les.query-measurement.v1` на пакет даёт по каждому запросу
`found / model_visible / not_visible / cards_omitted / chosen_rows` и группует их по
происхождению, а rollup держит число пакетов и каждый счётчик отдельно. Сравнивать суммарное
`found` нескольких пакетов с `model_visible` одного последнего вызова как единую потерю нельзя.

`found` — это пул, который поиск сматчил, а не срез, который пропустил
`model_evidence_k`. Замер 824/826/827 давал `found = 6` на каждом запросе именно потому,
что счёт снимался после обрезки: две величины неразличимы по построению, и потеря,
которую приносит потолок, невидима для любого читателя отчёта. Оба retriever и так
сообщали немодифицированный пул — `fusion_candidates` в браузере норм и `merged_count`
в каноническом RRF, — но инструмент его выбрасывал. Теперь число несёт каждая
доставленная карточка (`meta.matched_before_cap`), payload вызова добавляет
`matched_before_cap`, `verified_before_cap` и `evidence_cap`, а строка замера держит
`returned_within_cap` рядом с `found` и `found_basis` в одном из трёх состояний:
`pre_cap_pool` (потолок срезал реальный пул), `pool_within_cap` (пул уместился целиком),
`pool_not_reported` (число не пришло — запись кэша до 828 или пустой пул; падать на
`returned_within_cap` без метки означало бы выдавать потолок за объём базы). Поле
живёт в meta карточки и в payload: в промпт оно не рендерится, поэтому ни один
символ модельного входа от замера не зависит. Глубина поиска, `candidate_k` и
`model_evidence_k` не изменены — измерено то, что уже было.

`finish_reason=length` на вызове списков запросов обрабатывается адресно: последняя оборванная
строка не исполняется как запрос, модель просят дописать именно её (один раз), а список, в котором
что-то объявлено, не запрашивается заново. На пакет отведено не больше
`_MAX_SHEET_PASS_QUERY_CALLS = 3` вызовов — объявление, одна починка формата, одно продолжение;
наращивание числа попыток дефектом не считается.

## Таблица решения: reader и quality gate читают один и тот же формат (блокер § 1 и § 3, 29.09)

Reader ответа и gate закрытых статусов перечитывают один и тот же модельный текст:
если они разошлись в том, что считать строкой таблицы, решение модели попадает в
документ из одного текста, а оценивается по другому. Формат читает
`proxy/services/model_answer_table_service.py`, и reader
(`parse_model_rag_result`), и `parse_quality_table` вызывают его.

Разобрались три записи, каждая — по сохранённому в установленной версии ответу:

- `[Источник 1] | source_row | … |` — метка, которую требует сам prompt, приклеена к
  строке заголовка (чат-строка 506). Строка не начиналась с `|`, заголовок не
  узнавался, и обе позиции строки (`АР!R49`, `АР!R64`) пропадали: `parsed_rows = 0`
  при том, что модель решение записала. Снятие только этой метки — правка
  оформления; текст ответа возвращается дословно, значение каждой ячейки остаётся
  своим.
- `|:--|:--|` — выравнивающая ячейка из двух (и одного) дефиса (чат-строки 53, 55,
  76). С 8007b38a reader требовал не меньше трёх дефисов, и таблица из 38 строк
  ВОР!R4…ВОР!R41 не читалась вовсе.
- `source_row | row_role | …` без внешних `|` (чат-строка 330): внешние `|` в
  markdown необязательны, а reader на первой такой строке останавливался, и
  все разделы ниже первого терялись.

Обратная сторона терпимости: строка, которая заметно уже таблицы и не открыта как
табличная, — проза, и таблица на ней заканчивается; такой текст не дописывается
пустыми ячейками до «решения». Модельный `[Q4.H1]` или значение в квадратных
скобках внутри ячейки меткой не считается и остаётся в ячейке.

Измерено на всём сохранённом корпусе ответов (369 ответов с `|`, read-only
`chat_history`; `stage_b/live_829/rendering_diff_829.json`): восстановлено 5
ответов, которые не читались совсем (+128 позиций), изменено 8 ответов — строго
прирост (+286 позиций всего, 14470 → 14756), потерянных ответов и строк нет
(`lost_answers = 0`), и по 13 затронутым ответам каждая строка, прочитанная раньше,
присутствует после правки дословно, а текст ответа возвращается без изменений
(`stage_b/live_829/additivity_829.json`). Ни одно поле модели не заполняется и не
переименовывается кодом: reader стал читать то, что модель уже предъявила.

## Надёжность и readiness

- Параллельный model request ждёт публичный semaphore API до bounded timeout;
  приватный `_value` не читается. Отмена освобождает только реально полученный
  permit.
- HTTP/SSE/model-visible tool result получают стабильный код и операторский
  текст; класс исключения и diagnostic detail остаются в логах/trace.
- Readiness разделяет `backend_available`, `contract_complete`,
  `optional_stages` и per-query `query_quality`. Слабый отдельный запрос не
  делает исправный backend или контракт красным.
- RAPTOR по умолчанию `off`. ColBERT вызывается только при status `ready`,
  закрытом breaker и audited active-generation contract с полной multivector
  readiness; отсутствие такой генерации — обычный `not_ready` bypass.
- Приёмочный runtime может выставить
  `LES_STARTUP_BACKGROUND_MUTATIONS=false`: startup тогда не запускает repair,
  generation reconciliation и resume supervisors. Default остаётся `true` и
  виден в runtime registry.
- Admission различает загрузку точной локальной answer-model и чужой модели.
  Для уже резидентной модели действует отдельный жёсткий RAM floor; swap guard
  сохраняется. Chat не заменяет выбранный Ollama/MLX provider по уровню RAM.

### 867: terminal текущего пакета и независимые evidence cursors

`sheet_pass_question_tail` ограничивает ответ текущим исходным пакетом. Его
неусечённый terminal сохраняет авторские строки и завершает именно этот пакет;
следующее предложение содержит только ещё не показанные исходные строки. Даже
если модель не вернула решение части пакета, приложение не придумывает строки:
их locators остаются в source coverage gap и durable `remaining`.

`workbook_research_jobs.held_packet_json.terminal_packets` накапливает отдельные
snapshots с packet identity, literal queries, query offset, provenance и
addresses. `record_packet` и `pause` атомарно сохраняют предыдущие snapshots при
смене активного курсора. Query cache и immutable evidence с признаками реально
показанных bodies/native reads сохраняются отдельно; restart и document lineage
переносят их вместе. Схема SQLite не меняется. `reopen_locators` отдельно отмечает
явно открытые пользователем строки, не переписывая evidence snapshots.
Такой reopen сохраняет текущие operation IDs/revisions и пользовательскую
инструкцию в review baseline. При незавершённом предыдущем review его ещё не
пересмотренные решения сохраняются; после завершённой ревизии удалённые старые
операции из исторического baseline не восстанавливаются. Эта граница действует
по terminal конкретного исходного пакета, даже если другие пакеты ещё открыты;
повторный явный reopen до нового terminal сохраняет текущие IDs/revisions.

Same-request replay не предлагает закрытые пакеты повторно. Неиспользованные
кандидаты остаются для явного уточнения; их непрочитанные страницы не являются
source omission или требованием нового предметного ответа. Готовность документа
определяют source coverage, авторские proposals, доказательство выбранной нормы
и цены. `status_dimensions.deferred_evidence` отделяет Qx.Hy от пропущенных
исходных строк. Native requests до terminal и transport continuation усечённого
ответа сохраняют прежний путь. Расчёт и XLSX выполняются после прохода новых
пакетов без дополнительного предметного вызова модели.

Регрессии: несколько terminal пакетов с 35 запросами, native card/price reads,
неполный первый ответ без повторного предложения готовых строк, сохранение всех
cursors/cache/evidence после restart и lineage, явное снятие packet marker.
Offline gate не доказывает качество: обязательна installed live-проверка той же
318-строчной ВОР, model/provider/source/scope/pricebook identity и сравнение с B0.

Native continuation передаёт `NativeToolExchange` целиком через ContextGovernor:
assistant content и исходные function arguments/IDs сохраняются, каждый tool
reply связывается с тем же ID и содержит receipt с новыми immutable Qx.Hy refs.
Полные тела карточек остаются одной копией в required evidence registry. Native
batch с недопустимыми ID/arguments, неизвестным tool, повтором либо превышением
лимита не исполняется частично; transport protocol не меняет решение модели.

Query failure передаёт приватный typed `ModelQueryFailure` через provider wrapper
в существующую error history. `retrieval_trace` сохраняет session/model/connection
facts, finish reason, tokens/budget, counts/reasons declared parse и final text
последних восьми query calls (до 8192 символов каждого, с явными признаками
ограничения). Hidden thinking и credentials удаляются до ограничения текста.
SSE/HTTP error содержит только безопасные code/detail; arbitrary HTTP detail не
может подставить диагностический trace. Правила парсера и запросы модели не меняются.

## Draft 916 — bound initial identity inventory admission

`govern_model_rag_initial_messages` is shared by the direct B0 answer and the
initial B1 sheet answer. It first retains the existing conservative evidence
page. If that page leaves identities unshown, `inventory_expansion_page` offers

## Candidate 930 — a chosen шифр is priced only after its own card was delivered

Measured on installed 929 (`.test-tmp/repro_929_card_read_blocker.py` →
`artifacts/live_929/card_read_repro_930/repro.json`, both БАП cells): B0_DIRECT named 7 norms,

carried numbers in the delivered XLSX — for PDF!R4 «Защитное укрытие», 116 м² that was
151 446,11 руб. under a «Разработка проема…» шифр.

The rule candidate 930 enforces is the delivery half of § 3/§ 4 of
`QWEN_MVP_CLOSEOUT_2026-09-30.md`, and it stays inside the existing stage:

* `proxy/services/norm_card_proof_service.py` reads the fact the application owns — a work row
  naming a шифр whose cited ref has `card_body_shown is False` — and composes one bounded,
  visible proof request naming those refs and шифры. It names no norm, rejects none and reads
  nothing itself: `run_model_evidence_read_turn` ends a turn only when the model requests an
  evidence operation, so the read stays the model's action and its answer stays its decision.
* The sheet pass sends that request once per packet attempt
  (`LES_LSR_NORM_CARD_PROOF_READS`, refs capped at 6) and takes the answer again on the same
  governed messages. A model-issued `read_norm_card` executes through the existing path:
  receipts, `bind_model_requested_read_evidence`, durable `record_evidence_read`, then the
  native continuation. A second unread answer keeps its `norm_card_body_unread` gap and buys
  no further inference.
* `retrieval_trace.norm_card_proof_requests` records refs, reason, and how many reads the model
  actually made after the request, so the cost and the effect are both auditable.

Two counter fixes come with it, because § 3 asks for the difference between *found*,
*described* and *delivered*: `card_delivery_facts` no longer echoes the caller's boolean —
`card_body_shown` is derived from the rendered text, and a caller that claimed a body while
passing a pointer line is reported by `body_claim_disagrees_with_delivery` — and the
`grouped_model_evidence_pages` entry is recomputed from the chunks the expanded page actually
holds instead of keeping the pre-refit `full_body_hit_count`. In the 929 records the two views
of one packet disagreed in 6 of 24 `source_map` rows (delivered/body_visible true while the
same ref is listed in `deferred_body_refs`).

it does not by itself produce money — a position needs resources and prices read as well. The
measured requirement it serves is that a шифр nobody showed cannot be presented as a calculated
position. The narration/search boundary of § 3 is **not** solved here: measured over 1 117
declared lines from builds 901-929, 28 lines carry a second sentence and all 28 are
accompanying answer, but the customer's own row title «Тип 2. Открытый потолок. Обеспыливающая
покраска…» has the same shape and 1 013 of the 1 089 genuine search lines carry neither a

## Candidate 933 — a proof round that cannot be read may not erase the packet

Installed 932 measured the cost of the round itself. The БАП B1 cell came back with `work_rows 0`,
`rows_naming_a_norm 0` and `preliminary_amount 0.00` after a norm-card proof round whose answer was

Both rounds now rebind through `rows_after_proof_round(parsed_rows=…, previous_rows=…, chunks=…)`:

flag is written into `norm_card_proof_requests` and `resource_group_proof_requests`, so "the model
answered in prose" and "no round ran at all" remain two different facts instead of one empty entry.
The group ask resolves the book from this sheet pass's own basis (`sheet_price_basis`, through
`model_pricebook` with `explicit_only=True` and the recorded source hash re-checked), which is
known before the first price tool runs.

`tools/architecture_contract_gate.py` code `PROOF_ROUND_ERASES_PACKET_ROWS` pins three links: both
rounds call the helper, the helper has a branch that returns `previous_rows` and still rebinds
through `bind_row_evidence_ids`, and both records pass `answer_parsed`. Mutating the branch back to
`return [], False` makes
`tests/test_norm_card_proof_request_930.py::test_a_proof_round_answered_in_prose_delivers_the_packet_rows`

## Candidate 934 — one badly-valued row may not cost the packet every row it can read

Installed 933 measured the all-or-nothing reader on the customer's own БАП
(`artifacts/live_933/installed933_bap_b1/`). The model answered the packet `PDF!R18…R25` as one
closed JSON document — 6343 characters, 12 rows, `finish_reason = stop`, all seven packet locators
present — and wrote `"conversion_factor":1/100` inside three of them. The envelope parse failed on
that token, `decode_model_result_rows` returned nothing, and the run terminated with
`MODEL_RESULT_JSON_INCOMPLETE_RESULT`, `source_coverage_incomplete:1/20`,
`packaging_reason = ARTIFACT_KIND_UNRESOLVED` and no downloadable file. Eleven complete decisions
were discarded by the application, not withheld by the model.

`proxy/services/model_lsr_result_contract.py` now separates the two facts:

* `_container_end` bounds objects and arrays while honouring strings and escapes, so the reader can
  tell *unterminated* from *unreadable*;
* `_salvaged_candidate` walks the authored `rows` array element by element. An element that parses
  on its own is admitted **as its literal text**; an element that does not is returned as a broken
  row. If the container never closes, or no element parses, or an envelope member other than `rows`
  is unreadable, the function returns `None` and the refusal is exactly the old one — an unfinished
  answer is still refused whole, and the application never guesses which document kind the model
  meant;
* each broken row becomes a visible proposal `MODEL_RESULT_JSON_INVALID_ROW`
  (`unreadable_authored_json_row`) carrying the model's own bytes and its `source_row`. No value is
  computed for it, its locator stays uncovered if nothing else covers it, and no status is promoted.

Replayed against the live bytes (`.test-tmp/replay_authored_json_934.py`, report
`artifacts/live_934/authored_json_replay_934.json`): the same answer that produced 0 rows produces
**9 admitted rows covering all 7 locators** with 3 unreadable-row proposals, and the six pinned
unfinished forms — including `'{"rows":['` and `'artifact_kind: vor\n{"rows":['` — are still refused
with `MODEL_RESULT_JSON_INCOMPLETE_RESULT` and the full original transport preserved.

`tools/architecture_contract_gate.py` code `AUTHORED_JSON_ROW_LOST_WITH_ENVELOPE` pins both halves:
the reader must attempt the salvage before it reports an envelope incomplete, and the salvage must
bound its elements with `_container_end`. Reverting either reproduces 933 with a green test suite.
