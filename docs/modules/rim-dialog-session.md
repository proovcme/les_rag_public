# Диалоговая РИМ-сессия

Статус: реализован Mac-кандидат 0.26.4. Модуль расширяет `smeta_core`, не создаёт
второй сметный движок и не меняет профессиональные решения модели или сметчика.

## Поток

```text
XLSX/CSV
  → immutable source intake
  → ВОР revision
  → Qwen scope и batch catalog/search/read/submit
  → mapping revision → deterministic global review → user mapping lock
  → model/user-authored scenario
  → canonical RIM calculator → requirements
  → КАЦ/коэффициенты/уточнения → обязательный пересчёт
  → priced draft → user final lock → XLSX + audit
```

Состояние хранится в `storage/rim_sessions` как SQLite-граф append-only
ревизий. Запрос с устаревшим `expected_parent_revision_id` отклоняется, сессии
изолированы по владельцу, а административный доступ остаётся явным.

Долгий norm-mapping после каждого выполненного tool call атомарно сохраняет
в `rim_agent_checkpoints` server-produced checkpoint: полный диалог, catalog /
search / opened-card trace, принятые строки, remaining `work_id` и следующий
ход. Checkpoint привязан к SHA-проверяемому payload и точной immutable
VOR-ревизии, но сам не двигает `head_revision_id`. После рестарта или timeout
агент продолжает с последнего tool result и не повторяет уже выполненный
поиск/чтение. После сохранения итоговой mapping-ревизии checkpoint удаляется.

При resume Qwen получает короткий authoritative status: оставшиеся `work_id`,
актуальный остаток search/read/card/time budget и по каждой строке число
кандидатов, открытых карточек и поисков. Старое сообщение `budget exhausted`
не остаётся действующим, если новый процесс запущен с большим бюджетом.
Одинаковая фаза нескольких строк должна исполняться одним batch-вызовом. Если
кандидаты уже есть, а карточки не открыты, следующий вызов по этой строке —
`read_norms_batch`, а не дальнейшее расширение каталога.

Transport timeout structured mapping не считается schema-validation attempt:
checkpoint сохраняет blocker, но повторный запуск может снова сериализовать
те же model-owned решения. Точные строковые значения `true`/`false`, которые
локальная модель иногда возвращает для schema-boolean, нормализуются только в
объявленных boolean-полях tool contract; профессиональные значения и строки
не переписываются.

Идентичность проектного источника не принадлежит модели. При уточнении
черновика она может изменить формулировку работы и объяснение количества, но
`source_ref`, `source_refs` и `source_row` существующего `work_id` наследуются
из родительской VOR-ревизии. Новая производная работа допустима, только если
она ссылается на уже известные project source refs родителя. Нормативный источник хранится отдельно в mapping как
`norm_source_ref` и не может подменить строку исходного XLSX.

Mapping lock и final lock — разные пользовательские ревизии. Закрытие
requirement не обновляет старую расчётную трассу и не разрешает финализацию:
новый `priced_draft` появляется только после повторного детерминированного
расчёта.

## Строгий нормативный контракт

Для диалоговой РИМ-сессии разрешена только цепочка:

```text
browse_norm_catalog
  → search_norms_batch
  → read_norms_batch
  → submit_lsr_mapping
```

Qwen обязан сначала открыть model-visible паспорта пяти семейств из
`config/domain/smeta_normative_catalog.json`: официальное назначение, типовую
область, исключения, вопросы, нормативный акт и навигационный источник. Затем
модель отдельным вызовом фиксирует `family`, собственный `scope_reason` и
`confidence`; только после этого получает сборники выбранного семейства и
отдельным вызовом с собственной причиной выбирает `collections`. Ответ на
выбор сборника содержит вычисленный из активной typed SQLite
`smeta_norm_collection_passport_v1`: официальное название, характерные
отделы/разделы и таблицы, единицы, семейные исключения, вопросы и readable
source. Паспорт строится по текущей версии ФСНБ, а не поддерживается вручную.

`search_norms_batch` принимает только `scope_mode=scoped`; глобальный либо
неполный scope отклоняется до retrieval. `SmetaNormToolSession` проверяет
двухступенчатую трассу выбора. Если передан `table`, его префикс и фактическое
наличие проверяются внутри той же пары `base_type + collection`; таблица из
другой книги или сборника не попадает в retrieval. Только после этих проверок
фильтры передаются в `browse_norms_many()` — SQLite FTS/Qdrant RRF/rerank.
Старый текстовый `estimate_harness_service.search_norm()` не является точкой
входа этого модуля.

Тот же конфиг хранит пользовательский реестр источников РИМ с SHA исходной
`нормативка_под_РИМ.xlsx`: коэффициенты, Сплит-форму, ФСЭМ, КАЦ, НР и СП.
`rim_knowledge_service.py` передаёт Qwen только релевантные текущему этапу
карточки. Это навигация к `rules_store`/`price_store`/`fsem_store`/`kac_store`,
а не значения для расчёта; точные цифры по-прежнему читаются typed-сервисами.

Shortlist из RAG имеет роль навигации. Он может дать Qwen `norm_key`,
technology hints и `questions_to_ask`, но не является расчётным evidence.
Выбранная строка проходит только после `read_norms_batch`: mapping хранит
`card_opened=true`, `norm_source_ref`, редакцию и identity целиком прочитанной
карточки versioned structured store. Норма без открытой карточки блокирует
mapping lock и расчёт.

`questions_to_ask` из навигационной карточки передаются Qwen отдельным
ограниченным ходом. Модель выбирает один наиболее ценный вопрос, формулирует
его по-русски и сохраняет как открытый вопрос сессии. В UI варианты ответа
показаны кликабельными кнопками; свободный текст тоже допустим. Короткий
следующий ответ интерпретируется относительно этого вопроса, а не запускает
новый workflow.

Для локальной Qwen 3.5 9B преобразование спецификации начинается с bounded
transport-пакета в 5 исходных позиций. В первом действии доступен только
`draft_work_schedule`; вопрос разрешается после сохранения source-linked
черновика. Это ограничение транспортного контекста, а не автоматический выбор
работ кодом.

MLX Host сохраняет bounded KV/prefix cache на стабильной границе сообщений
до нового ответа assistant. Поэтому следующий tool-turn повторно использует
общую часть system/user/tool history, тогда как allocator cache по-прежнему
очищается после хода, а веса остаются тёплыми до TTL. В OpenAI-совместимом
ответе reuse виден как `usage.prompt_tokens_details.cached_tokens`.

## Расчёт и сценарии

Код не строит Cartesian product профессиональных альтернатив. Он показывает
теоретическое число комбинаций и считает только совместимый сценарий,
составленный моделью или пользователем. Лимит по умолчанию — 1000; превышение
возвращается как blocking issue.

Сценарий преобразуется в canonical visible rows и передаётся
`smeta_core.application.calculate_visible_rows_revision`. Пропущенная цена
читается из exact resource trace и создаёт blocking `kac`, а не нулевую цену.
Имеющийся РИМ renderer строит графы 1–12; дополнительными листами идут
`Недостающие данные` и `Аудит`.

## API и UI

Роутер `proxy/routers/rim.py` предоставляет owner-scoped `/api/rim/sessions/*`:
сессии и ревизии, импорт/ВОР, model tools и agent turn, mapping/XLSX/global
review/lock, сценарии и расчёт (`/combinations/calculate` или `/recalculate`),
requirements, final lock, export и audit.

NiceGUI-поверхность `sovushka/pages/rim.py` доступна как lazy-вкладка
«РИМ-смета». Она использует общий UI kit и показывает источник, ревизию,
основание, статус и блокировки для ВОР, mapping, review, requirements, ЛСР и
финализации. Список owner-scoped сессий позволяет вернуться к предыдущей
работе; отсутствующий либо устаревший сохранённый ID заменяется последней
доступной сессией без ложного `404`.

## Проверки кандидата

- unit/API/XLSX/state/UI тесты находятся в `tests/test_rim_*.py` и
  `tests/test_sovushka_uikit.py`;
- isolated Mac browser smoke проверен на desktop и 390 px без горизонтального
  переполнения;
- реальная `СКС.xlsx` распознана как спецификация: 70 позиций, 3 раздела,
  structural issues отсутствуют; после ужесточения draft-schema Qwen сохранил
  первые 5 строк с обязательными `work_name`, `unit`, `quantity`,
  `quantity_origin`, `source_ref` и задал технический вопрос «монтаж и
  подключение входят в ВОР или только поставка?» с двумя вариантами ответа;
- реальный Mac Qwen 3.5 9B первым вызовом выбрал `browse_norm_catalog`, не
  придумав шифр;
- реальный isolated Mac cache-probe на Qwen 3.5 9B повторно использовал
  `14 968` из `14 996` prompt tokens; второй ход занял `2,24 с` после
  холодного первого хода `139,17 с`;
- Mac Qwen 3.5 9B устойчиво проходит каталог пошагово; измеренные ходы заняли
  примерно 51–94 с. Ошибочный live scope `ГЭСН 34 + 08-02-001` стал
  регрессией: typed-каталог показывает названия `ГЭСН 34`, `ГЭСНм 10` и
  `ГЭСНм 08`, а несовместимая таблица отклоняется до поиска.
- продолженный пятистрочный Mac-прогон `СКС.xlsx` восстановил прежнюю VOR
  revision после process/model restart, сохранил количества `2/8/2/4/2` и
  исходные строки `6–10`. Qwen сама выбрала `ГЭСНм`, затем сборник `10`, а
  первый search передал точный scope `base_types=["ГЭСНм"]`,
  `collections=["10"]`;
- для шкафа Qwen дошла до полного typed read 12 карточек. Полные карточки
  показали ложноположительные навигационные совпадения: кабельные работы,
  телефонный шкаф на фундаменте, железнодорожную прокладку и сосуды/аппараты.
  Ни одна карточка не была принята кодом;
- живой mapping не завершён: после чтения всех 12 карточек checkpoint вырос до
  `1 126 516` байт, structured prompt — до `42 944` токенов, cold prefill
  занял `398,28 с`, после чего transport достиг timeout `600 с`. Сохранены
  `structured_mapping_timeout`, открытые карточки и следующий ход. Это
  подтверждает durable recovery, но одновременно фиксирует blocker для
  следующей версии: thin checkpoint/context builder вместо возврата полного
  tool transcript.

Legion и живые LES-сервисы этим кандидатом не изменялись.
