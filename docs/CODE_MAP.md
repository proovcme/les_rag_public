## Алгоритм-доки (детерминированные ядра, 0 LLM)

Канон логики, которую LLM не трогает (числа/преобразования считает код, ADR-11). Читать

Сервисы `proxy/services/asbuilt_intake_service.py` (+ `asbuilt_ocr.py`), чат-канал `asbuilt_chat_service.py` (Совушка вызывает сама: «вытащи смонтированный объём из «<путь>»»), эндпоинт `POST /api/field/extract-asbuilt`, CLI `tools/asbuilt_extract.py`. Выбор vision-модели — бенч `tools/asbuilt_ocr_bench.py` (recall по якорям + латентность).
- **[ALGO-les-md.md](ALGO-les-md.md)** — `LES.md`/`ЛЕС.md`: файл-контекст папки (CLAUDE.md для ЛЕС). frontmatter (проект/объект/стадия/шифр/директивы/ignore) + тело→контекст чата; привязка папки к проекту, авто-черновик из скана. Не создаёт scope и не выбирает объект за модель.
- **Сметная декомпозиция** — текущий маршрут режима «Смета»: модель сама раскладывает объект на работы и вызывает инструменты; харнесс (`estimate_harness_service.run_estimate_harness`) даёт `search_norm`/`add_position`, `search_norm` использует общий `candidate_selection_service`, проверяет применимость норм, единицы и объёмы, а код считает только прошедшие gates. Если пользователь явно просит «придумай/прикинь/по допущениям», модель может задать геометрию и слоты как `assumptions`, а ответ маркируется как сценарная прикидка. `chat.py` отдаёт краткую операторскую сводку в `answer` и полную ресурсную сметную расшифровку в payload `artifact`. Старый объектный слой удалён: готовые объектные составы не являются маршрутом пользовательской сметы.
- **[ALGO-normcontrol.md](ALGO-normcontrol.md)** / **[DOC_REVIEW_GOST_R_21_101_2026_PLAN.md](DOC_REVIEW_GOST_R_21_101_2026_PLAN.md)** — нормоконтроль: formal NK-01..04 (`normcontrol_service`) + RAG-led `doc_review_service` по ГОСТ Р 21.101-2026. Сервис `proxy/services/notebook_study_service.py`, подключение в `proxy/routers/chat.py`. Это navigation layer, не deterministic final и не evidence.
- **Notebook-study policy (0.24.0.41-0.24.0.45):** при найденном контексте `HALLUCINATION/UNKNOWN` от валидатора по broad-study понижается до `UNVALIDATED`, чтобы Т.О.С.К.А. предупреждала, но не стирала модельную инженерную сводку generic fallback. Пустой контекст по-прежнему блокируется. Общие запросы по объекту/проекту помечаются `breadth=wide` и обходят answer-cache; точные вопросы остаются узким RAG. Для notebook-study нет отдельного короткого token-cap; ответ масштабируется по широте запроса, а не режется до фиксированного числа строк. Artifact `Инженерный блокнот` идёт как `mode=markdown`, начинается с найденных материалов, а служебный маршрут чтения уходит вниз.
- **Scope UUID compatibility (0.24.0.43):** legacy UI может прислать выбранный датасет как UUID в `dataset_filter`; `scope_service.resolve_scope` и `retrieval_service.resolve_dataset_ids` трактуют такой filter как dataset id, иначе wide notebook-study теряет `_dataset_ids` и откатывается в обычный широкий RAG.
- **[ALGO-workflow-plan.md](ALGO-workflow-plan.md)** — общий `workflow_plan_v1` поверх ответов: workflow, required/missing inputs, evidence policy, claim summary, source summary, blockers и next actions. Сервис `proxy/services/workflow_plan_service.py`; подключён через `answer_contract_service.decorate_payload()` и `doc_review_service.review_to_json()`, в Совушке отображается как операторский workflow-статус и технический след.
- **[ALGO-external-radar.md](ALGO-external-radar.md)** — радар внешних источников: configured/browse roots + `file_map.db` + MetaDB `documents.source_path`, shallow-обзор без reindex/OCR/LLM. Сервис `proxy/services/external_radar_service.py`; API `GET /api/external-radar/summary`; UI Самовар.

## Поток запроса (чат) и индексации

**Запрос:** `POST /api/chat` → `runtime_admission` (очередь/режим) → `query_router` (mail/table/clause/generic) → `retrieval_service` (semantic_cache → Qdrant) → `context_memory_service` + `dataset_memory_service` (deep-паспорт, typed-карта датасета и optional model reader-pass как фон/навигация, НЕ evidence; prompt-лимит датасетов) → для явного broad-study по выбранной области `notebook_study_service` строит reading plan и добирает section retrieval → `saferag_service` (C-RAG: контекст + source-map `Источник N` + валидация фактов через MLX `/api/validate`) → `runtime_dispatcher` (MLX `/v1/chat/completions`, стрим) → ответ + `sources`/`source_map` + `latency_phases` + статус валидации + `scenario`/`answer_contract` + мягкий `answer_contract_check` + общий `workflow_plan_v1`; Совушка сохраняет план в metadata сообщения и показывает статус/финальность в чипах, а `workflow_id`/missing/actions — в техдеталях. Явный режим `smeta` до RAG собирает параметры объектной сметы из истории текущей `session_id`; free/read-attachment LLM-пути подмешивают `session_memory` как фон.

**Индексация:** `POST /api/datasets/{id}/upload` → `document_router.route_document()` → `converter.convert_to_markdown()` (pdf/docx/xlsx/eml/dxf/ifc) → `StructureAwareSplitter` (бережёт нумерованные пункты ГОСТ/СП) → typed metadata (`content_layers`, `file_kind`, `document_role`, `source_granularity`) → батч-эмбеддинг через MLX `/v1/embeddings` → `upsert` в Qdrant → синхронизация `lexical_chunks` из тех же payloads для FTS/notebook/hybrid → метаданные и typed-memory sidecar в SQLite (`data/les_meta_qwen.db`).
