# Проекты, память и документы: направление продукта

Дата: 2026-09-05. Статус: приоритеты владельца зафиксированы; первый dev increment
проектов и явной памяти реализован в 0.31.0, не установлен и не опубликован.
Фактические границы и проверки: [модуль](../../modules/project-workspace.md).

## Подтверждённые границы

- ЛЕС — публичный продукт. Legion — приёмочный хост, не требование к пользователю.
- Целевой контур — локальные модели 9–100B. Облачные модели можно подключать,
  но они не являются обязательной частью сценария.
- Реранкер выключен по умолчанию; включение — галочкой в чате. Дальнейшее
  исследование его качества сейчас уступает проектам, памяти, документам и UI.
- Нужны проекты, управляемая память/контекст, новые формы документов и vision.
- Модель принимает профессиональное решение; код считает и оформляет документ.
- Память пополняется явно (выбор владельца); окно памяти — утверждённый эталон
  интерфейса для всего ЛЕС. Фирменный зелёный сохраняется во всех действиях.
- Текущий UI-этап ограничен чатом и сопутствующими окнами. Конфигурация и другие
  разделы исключены из текущей доработки по последнему уточнению владельца.

## Что уже есть в коде

- `project_service.py`: проекты и связи с датасетами/другими сущностями.
- `typed_memory_projection_service.py`: ограниченная проектная advisory-проекция
  существующих хранилищ; память не становится evidence.
- `context_governor_service.py`: бюджет контекста и явный список исключённых объектов.
- `routers/memory.py`: административное управление Memory Core; это ещё не
  удобная пользовательская память в рабочем пространстве проекта.

## Предлагаемый ближайший результат

Проект открывает последний чат и объединяет его чаты, выбранные источники,
готовые документы и видимую память. Создание проекта требует только названия.
Обычный чат остаётся доступен без проекта.

Память разделяется на пользовательские предпочтения и записи конкретного
проекта. Пользователь видит, исправляет, исключает и удаляет записи. Другие
чаты не загружаются целиком; сведения из них не становятся подтверждёнными
фактами автоматически. Для записи сохраняются происхождение и статус.

На каждый запрос отбираются компактные релевантные записи; подробности доступны
по адресу. Бюджет определяется фактическим окном подключённой модели, а не
предположением о большом облачном контексте. Источники ответа имеют приоритет
над памятью. В UI видны использованные записи и исключения из контекста.

Новые формы: сначала ВОР и коммерческая смета, затем импорт собственных DOCX
как шаблонов с сохранением оформления. Vision расширяет чтение сканов,
изображений и чертежей при наличии соответствующей возможности модели.

## Приёмка будущей реализации

- Основной сквозной сценарий выполняется на локальной 9B-модели.
- В пределах 9–100B используется один путь, без обязательного облачного вызова.
- Разные проекты не получают чужую память; обычный чат не наследует проект.
- Исправленная/исключённая запись корректно влияет на следующий model input.
- Память не вытесняет обязательные источники и не подменяет их в документе.
- Повторное оформление готового результата не требует нового решения модели.

Тесты кода не заменяют живую оценку качества на локальной модели и реальных
документах. Конкретные budgets и поддерживаемые vision-модели требуют проверки.
