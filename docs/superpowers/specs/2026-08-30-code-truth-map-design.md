# 0.30.5 — карта правды о коде

Статус: дизайн утверждён владельцем в диалоге 2026-08-30; реализация ещё не начата.

## Цель

ЛЕС должен отличать фактически достижимый продуктовый код от runtime-помощников,
инструментов, тестового наследия и отключённых продуктовых поверхностей. Документация
и статус `✅` не могут называть функцию рабочей только потому, что файл существует или
проверяется тестом.

## Фактическая исходная проблема

Текущая статическая карта показывает 14 `DORMANT_CANDIDATE`, но краткий отчёт скрывает
ещё 28 файлов внутри `proxy/` и `sovushka/`, достижимых только из тестов и утилит.
Совокупно это 42 файла и 7439 строк вне доказанного product path. Все они попадают в
устанавливаемый Windows runtime через широкие prefix-правила manifest.

Среди них находятся принципиально разные объекты:

- очевидный исторический хвост;
- отдельные dev/build-инструменты;
- product skeletons и backlog;
- временно отключённый Mail UI, который будет возвращён после переработки;
- ошибочная отдельная поверхность RIM UI, не являющаяся частью продукта;
- старый deterministic/scenario harness;
- внешний compatibility shim с недоказанными потребителями.

Поэтому автоматическое удаление по одной статической метке запрещено.

## Границы 0.30.5

### Входит

1. Генератор карты публикует две независимые оси:
   - доказанная достижимость: product, runtime helper, test/tool only, unresolved;
   - размещение и поставка: product tree, test/tool tree, Windows shipped, способ
     попадания в manifest (`prefix` или `exact`).
2. Человеческая карта отдельно показывает:
   - product-tree код, живущий только тестами/утилитами;
   - весь shipped, но не product-reachable Python-код;
   - отключённые пользовательские поверхности;
   - ограничения статического анализа.
3. MODULE_INDEX и CODE_MAP приводятся к фактическому состоянию:
   - Mail backend активен, нынешний Mail UI временно отключён и будет меняться
     перед возвращением;
   - RIM backend активен через универсального агента/API, отдельный RIM UI ошибочен
     и предназначен к удалению;
   - test/tool-only сервисы не называются частью боевого chat path;
   - skeleton/backlog не получает `✅` рабочего продукта.
4. Тесты защищают отсутствие скрытого production mounting, но больше не требуют
   сохранять сам dormant-файл как ценность.
5. Карта и документация проверяются штатным `make verify` / `make test`.

### Не входит

- удаление или перенос Python-файлов;
- изменение пользовательской навигации;
- включение или переработка Mail UI;
- удаление RIM UI (это отдельная механическая группа следующего этапа);
- изменение `proxy/smeta_core/**`;
- изменение model/RAG/tool execution;
- сужение Windows runtime manifest;
- публикация, deploy или обновление установленного ЛЕС.

## Статусы документации

- `✅` — пользовательский или runtime path доказан от боевой точки входа и док
  соответствует коду;
- `🟡` — backend/часть функциональности активна, но заявленная поверхность временно
  отключена, неполна или граница док↔код расходится;
- `🗄` — исторический или отключённый слой, не являющийся текущей инструкцией;
- `📋` — спроектировано или сохранено как backlog, но не является активным продуктом.

Статус относится к заявленной функциональности целиком. Нельзя выдавать активный backend
за доказательство работающего UI.

## Изменения генератора

JSON сохраняет существующий детерминированный inventory и добавляет для каждого файла:

- `tree_role`;
- `windows_runtime_shipped`;
- `windows_runtime_via`;
- отдельную причину reachability;
- явный признак `product_tree_non_product_path`.

Markdown показывает агрегаты и полный короткий список product-tree non-product файлов.
Ни один статус не называется доказательством мёртвого кода.

## Проверки

Точечный контракт должен доказать:

- `proxy/app.py` остаётся product-reachable;
- `tools/windows_update_engine.py` остаётся отдельным runtime helper;
- `sovushka/pages/mail.py` и `sovushka/pages/rim.py` помечены как product-tree,
  Windows-shipped и не product-reachable;
- все 42 выявленных файла видны в человеческой карте;
- prefix/exact manifest coverage рассчитывается фактически;
- generated Markdown/JSON не расходятся с репозиторием;
- production shell не импортирует отключённые поверхности.

Полный гейт: `make verify`, `make test`; версия Tauri проверяется после обязательного
version sync. Живые сервисы и пользовательские данные не требуются.

## Результат и следующий этап

0.30.5 не уменьшает кодовую базу. Он создаёт проверяемую границу, после которой 0.30.6
может удалить только доказанный исторический хвост небольшими независимыми группами.
Ошибочный отдельный RIM UI входит в такую механическую группу: его удаление не меняет
живой RIM backend и работу универсального агента. Mail UI сохраняется для последующей
переработки и возвращения, но его текущая реализация не объявляется стабильным продуктовым
контрактом. Compatibility shim и сметный монолит остаются отдельными решениями и не
попадают в механическую уборку.

## Откат

Изменение затрагивает только генератор, generated inventory, тестовые контракты и
каноническую документацию. Откат — возврат одного implementation-коммита; runtime и
данные не меняются.
