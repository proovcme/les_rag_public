## Живой Qwen3.5:9b → RAG → XLSX

Установленный backend0.31.3/build709 не менялся в0.31.4/0.31.5. Настоящий исходный
XLSX, обычный зарегистрированный чат, factory estimator, reranker=false, выбранная
область all. Не fixture и не подмена исходных строк.

- Первый запрос: текстовый отказ, таблицы нет — **не прошёл**.
- Уточнение о пустых полях/MISSING:5 строк, неверные evidence refs — **не прошёл**;
  упаковка корректно заблокирована.
- Явный формат: `source_row, title, unit, quantity, norm_code, evidence_refs, missing`;
  refs только из возвращённых Qn.Hm, неизвестные norm_code/refs пустые, пропуски
  объяснены, профессиональные решения остаются за моделью — **прошёл**.

Успех:6 запросов модели,5 строк `accepted_unchanged`, XLSX12877bytes,
SHA256 `79a45487e04fbfc7f3bdb00af22602079188f7d32e8581f76bec8a7635034fdf`.
Проверены скачивание, ZIP CRC и наличие workbook.xml. Два URL в ответе указывали
на один файл — это **один XLSX**, не два разных результата.

Это доказательство конкретного запроса с явным форматом. Общую устойчивость9B
для сложных смет и автоматическое исправление её ошибок оно не доказывает.
Не менять выбранные нормы/ссылки руками ради зелёного; failed прогоны сохранять.

## Выпуск и восстановление

`make release` фиксирует exact commit/tree/версию/SHA, gate receipt и каждую попытку
install→smoke→rollback→reinstall. Build709: первая попытка упёрлась в холодную
загрузку сметного каталога, откат вернул708; тот же запрос затем27.2s и0.25s.
Повтор **тех же bytes**, без ослабления timeout/gates, принят. Не считать failed
попытку успешной и не переписывать её квитанцию. Окончательный release status
проверяется отдельно по artifact receipt и публичным assets.
