# ЛЕС 0.24.16

- Общий VPS-обновлятор вынесен из process tree приложения в независимую интерактивную задачу Windows.
- После патча новый Tauri runtime запускается отдельной задачей; успех фиксируется только после API/UI health-check.
- При ошибке файлы восстанавливаются из backup, а оператор получает однозначный статус перезапуска.
- `0.24.15` не считается совместимой базой VPS-патчей из-за Windows job-object lifecycle; канал начинается с `0.24.16 / build 427`.
- В Windows-настройках больше нет MLX и Mac-полей: локальный production-провайдер — Ollama; выбранная модель применяется после явного «Сохранить».
- В чате удалено меню «Доп. действия». Рядом с «Отправить» остались понятные «Настройки ответа» с единственным рабочим выбором длины; внутренняя память/LES.md больше не печатается при просьбе уточнить область.
- Интерфейс стал компактнее; список файлов выбранной области сворачивается, панель артефактов открывается постоянной кнопкой, а «Датасеты» доступны прямо из чата. «Админка» переименована в «Конфигурацию», шестерёнка — в подписанную кнопку «Настройки».
- Просмотр PDF глазами разрешает имя файла до оригинала, использует отдельную `gemma4:12b` и читает весь лист, штамп и легенду отдельными bounded-вызовами. Текстовый PDF-reader больше не считается визуальным просмотром.
- Windows PDF-ingestion чинит UTF-8/Latin-1 mojibake до нарезки и эмбеддинга (`План` больше не превращается в `ÐÐ»Ð°Ð½`). «Ремонт» сам находит повреждённые старые PDF, ставит только их на переиндексацию и сразу запускает видимую фоновую задачу.
- Модель обычного чата больше не назначается сметным агентом неявно. В настройках отдельно выбираются основная и резервная модели для смет; чистый прогон Gemma возможен без резерва. При включённой подстраховке текст вместо обязательного tool-call повторяется с требованием вызвать инструмент, а смена модели фиксируется явно.
- Локальный сметный agent использует нативный Ollama `/api/chat`: OpenAI-compatible endpoint терял tool-calls Gemma, хотя модель и нативный Ollama их поддерживают.
