# Проверка ПД и РД по чек-листам

## Назначение

Модуль собирает проверяемое evidence по корпоративным перечням входного
контроля и формирует построчную ведомость. Это профиль общего нормоконтроля
ЛЕС, а не отдельный экспертный движок и не генератор финального ответа.

Рабочая поверхность находится в **«Конфигурация → Инструменты → Проверка
проекта по чек-листу»**. Отдельная публичная страница `/nc` и отдельный
checklist-chat в текущий контур не входят.

## Пользовательский путь

1. Выбрать чек-лист ПД или РД.
2. Выбрать проектный датасет и, при наличии, датасеты ТЗ/СТУ/изысканий.
3. Ограничить прогон одной дисциплиной либо проверить весь перечень.
4. Открыть строку результата и изучить найденные источники.
5. Зафиксировать решение инженера: подтверждено, есть замечание или не относится.
6. Выгрузить XLSX, HTML или JSON.

В интерфейсе `evidence-статус` отделён от решения инженера. Код может сообщить,
что найдено подтверждение, формальная проблема или нужен добор, но не объявляет
проект соответствующим и не пишет ответ в чате за модель.

## Контракт

```text
выбранный checklist + явный dataset scope
  → inventory и адресный retrieval
  → typed readers / formal checks / ПП РФ №87
  → evidence с source_ref либо честный missing/manual
  → immutable run
  → отдельные решения инженера
  → XLSX / HTML / JSON
```

- ПД: 335 критериев, 10 разделов.
- РД: 692 критерия, 26 дисциплин.
- Имя файла без контентного фрагмента не подтверждает критерий.
- Отсутствие evidence не является нарушением и не является соответствием.
- Числа и формальные сравнения выполняет код.
- Профессиональное объяснение и итоговый вывод принадлежат модели; решение о
  приёмке принадлежит инженеру.
- `source_dataset_ids` не расширяются скрыто.

## Точки входа

- API: `proxy/routers/checklist_review.py`;
- evidence-движок: `proxy/services/checklist_review_service.py`;
- шаблоны: `proxy/services/checklist_template_importer.py`,
  `config/checklists/glorax_{pd,rd}_2026.json`;
- формальные правила: `proxy/services/checklist_param_rules.py`,
  `proxy/services/pp87_composition_service.py`;
- отчёты: `proxy/services/checklist_report_service.py`;
- UI: `sovushka/checklist_review_panel.py`,
  `sovushka/checklist_review_view.py`.

## Ограничения

- Полный прогон 335/692 пунктов пока синхронный; следующий архитектурный шаг —
  job/checkpoint/progress без удержания HTTP-запроса.
- Spatial/visual пункты остаются `manual_required`, пока нет надёжного
  CAD/BIM/layout evidence.
- DOCX/PDF фирменная форма отчёта не реализована.
- Качество зависит от полноты выбранного корпуса и наличия текста/OCR.
