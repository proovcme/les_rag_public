# Постмортем выпуска 2026-09-01

## Что было не так

- Рабочий код и выпуск были ошибочно связаны с повторными полными NSIS-сборками,
  хотя изменения допускали cumulative soft patch.
- Ошибки упаковки обнаруживались после дорогих стадий: preflight не проверял
  full-feed при явно переданном base и опубликованный набор не всегда содержал
  release receipt.
- Unit-тесты доказывали отдельные функции, но не пользовательскую транзакцию в
  установленном ЛЕС: выбранная модель → выбранный RAG → ответ → автоматический
  XLSX → цены и формулы.
- Readiness смешивал native sparse vector с legacy lexical sidecar и сообщал
  красный RAG при исправных named `dense + bm25_sparse`.
- Парсер мог показать ответ модели неизменным, но передать упаковщику уже
  перенумерованные строки и урезанные шифры.
- Bounded model-authored RAG мог незаметно вызвать document-router с отдельным
  JSON/LLM-запросом и широким scroll, а конфликты готового XLSX терялись в
  безопасной проекции результата.

## Исправление процесса

1. Сначала классифицировать diff: soft patch не запускает NSIS.
2. До дорогих стадий проверять ancestry, allowlist, full-feed, version и полный
   перечень будущих release assets.
3. Один immutable candidate устанавливать, принимать, откатывать, повторно
   устанавливать и публиковать без пересборки между стадиями.
4. До публикации выполнять сценарии в установленном приложении: обычный чат,
   user RAG, estimator с независимыми ВОР и автоматическим XLSX.
5. Release receipt является обязательным публичным asset; postflight сверяет
   tag, public `main`, feed и SHA каждого скачанного файла.
6. Ошибка тестовой инфраструктуры не маскируется как ошибка продукта, но и не
   разрешает публикацию без эквивалентного доказательства.
7. Model-authored RAG идёт непосредственно в native RRF с шестью карточками на
   запрос; `source_row` сохраняется до XLSX, а `missing/blockers` остаются
   видимыми как bounded `partial`-диагностика без повторного вызова модели.

## Незакрытый долг

- Кнопка «Проверить ЛЕС» должна запускать тот же установленный пользовательский
  transaction probe, а не показывать только сохранённый внешний статус.
- Локальный `main` должен быть выровнен с public `origin/main` после принятого
  выпуска без merge расходящихся историй.
- Размер полного installer остаётся отдельной задачей; hotfix не должен ждать
  её решения и публикуется cumulative patch-каналом.
