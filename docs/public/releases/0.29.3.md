# ЛЕС 0.29.3 — Windows release

Дата выпуска: 29 августа 2026 года  
Версия продукта: `0.29.3`  
Номер сборки: `631`  
Версия desktop package: `5.1.631`

## Коротко

0.29.3 собирает ЛЕС в понятную систему узлов: Совушка отвечает за пользовательский интерфейс, backend ЛЕС — за документы, RAG, память и инструменты, а модели и Qdrant подключаются как независимые внешние сервисы. Система может работать целиком на одном Windows-компьютере или быть разделена между несколькими доверенными узлами.

Это большой foundation-релиз, а не обещание полностью автономного инженера. Основной production-контур — Windows 10/11 x64. Некоторые уже существующие внутренние модули намеренно скрыты до отдельной пользовательской приёмки.

## Что вошло

### Совушка

- единый NiceGUI frontend для Tauri, браузера и устанавливаемой PWA;
- адаптивная мобильная компоновка;
- более лаконичная навигация и composer;
- единый экран подключений моделей;
- «Студия» и CAD/BIM показаны как недоступные будущие функции, а не как рабочие кнопки;
- почта убрана из основной навигации до завершения отдельного workflow.

### Подключения моделей

- реестр версионируемых OpenAI-compatible подключений;
- независимые роли ответов, эмбеддингов и запасной модели;
- loopback, частная сеть LAN/ZeroTier и удалённый HTTPS endpoint;
- capability probes для chat completions, streaming, tools, models и embeddings;
- masked API secrets и safe browser projection без выдачи ключа;
- явная привязка роли к точной ревизии подключения;
- presets контекста для локальных 9B/35B сценариев без engine-name routing в основном workflow.

Проверенный сетевой Qwen 35B доступен через защищённый OpenAI-compatible proxy и поддерживает chat, streaming и tools. В 0.29.3 он остаётся `shadow`: ЛЕС собирает доказательства совместимости, но не делает его главным ответным маршрутом без отдельной live acceptance и promotion receipt.

### Документы и RAG

- одна contract-versioned named collection вместо неназванных или параллельных индексов;
- named vectors `dense` и `bm25_sparse`;
- обязательный native Qdrant RRF;
- lexical safety channel после native RRF;
- общий parent/context expansion;
- exact readers для строк и карточек без подмены профессионального решения кодом;
- typed project memory отделена от evidence и ограничена ContextGovernor;
- unscoped чат больше не ломает память и инструментальный shortlist.

На контрольном Legion-контуре восстановлена коллекция из 101 366 точек. Живой production-запрос подтвердил `qdrant_native_hybrid+parent_card`, fusion `qdrant_rrf+lexical_safety_rrf` и каналы `dense`, `qdrant_sparse`, `lexical`.

### Инструменты

Инструменты проходят через Registry → Broker → Executor. Один ответ селектора создаёт не более одного canonical-вызова; остальные намерения остаются ожидающими. Это последовательный контролируемый цикл, а не бесконечная автономная цепочка.

Доступ к данным fail-closed: отсутствие выбранной области не превращается в разрешение читать весь корпус. Результат инструмента возвращается модели как evidence, а не становится профессиональным решением сам по себе.

### Режимы запуска

- `full`: Совушка и backend на одном узле;
- `backend`: headless API без UI-порта;
- `ui`: Совушка подключается к явно указанному backend и не запускает его зависимости.

Tauri использует `full`. Разделённые профили предназначены для операторского развёртывания, включая схему «Совушка на VPS, backend и модели на доверенных узлах». Автоматического VPS-мастера в 0.29.3 ещё нет.

### Windows installer и обновление

- per-user Tauri/NSIS installer без требования прав администратора;
- встроенные portable CPython, uv, exact `uv.lock` и офлайн dependency cache;
- отдельные application и persistent-state trees;
- изолированная установка exact artifact до обновления production;
- транзакционная замена application tree;
- recovery directory для отката;
- проверка version, API, UI, Qdrant/RRF и process contracts;
- прямые фоновые `pythonw.exe` без видимых console wrappers.

Размер установщика около 500 МБ связан прежде всего с офлайн Python runtime, locked dependency cache и immutable release assets. Модели, Qdrant, Docker и пользовательские данные в этот размер не входят. Состав payload будет отдельно проаудирован после выпуска на дубли, кэши и необязательные файлы.

## Что не входит в установщик

- Ollama, FreeToken и Lemonade;
- локальные или облачные модели;
- Qdrant;
- Docker Desktop;
- пользовательские документы, почта и история;
- Qdrant snapshots и SQLite runtime state;
- API-ключи и пароли.

Все эти сервисы, кроме пользовательских данных, подключаются снаружи. Docker — лишь один возможный способ эксплуатации Qdrant и не является частью lifecycle ЛЕС.

## Проверенная конфигурация Legion

- Windows 11 x64;
- ЛЕС `0.29.3`, build `631`, desktop `5.1.631`;
- внешний native Qdrant `1.19.0` на `127.0.0.1:6333`;
- alias `les_rag` → `les_rag_v563`;
- 101 366 точек, dense dimension 1024 и `bm25_sparse`;
- Ollama с `bge-m3:latest` как embedding provider;
- Qwen 3.6 35B на Mac mini через ZeroTier как проверяемый shadow answer node;
- UI и API доступны только в настроенном локальном контуре.

Эта конфигурация доказывает работоспособность указанного контура, но не встраивает адреса машин или модели в defaults продукта.

## Известные ограничения

- Windows binary не подписан Authenticode и может вызвать предупреждение SmartScreen;
- Qwen 35B ещё не повышен до authoritative route;
- Studio, CAD/BIM UI и основной почтовый workflow скрыты;
- готового one-click VPS deployment нет;
- PWA требует доступный backend и не выполняет offline-запросы;
- macOS/Linux desktop acceptance не равна Windows release acceptance;
- optional RAPTOR, ColBERT и cross-encoder требуют собственных preflight и acceptance; их отсутствие не отменяет native RRF;
- текущие разделы «Настройки» и «Конфигурация» частично дублируются и будут объединены после выпуска.

## Установка и обновление

1. Скачайте `LES-Setup.exe`, `LES-Setup.exe.sha256` и `latest.json` только из [GitHub Releases](https://github.com/proovcme/les_rag_public/releases/tag/v0.29.3).
2. Сверьте SHA-256 установщика.
3. Запустите `LES-Setup.exe`.
4. После запуска откройте конфигурацию и назначьте отдельно answer model, embeddings и Qdrant.

Обновление сохраняет `%LOCALAPPDATA%\LES`. Заменяется только `%LOCALAPPDATA%\Programs\LES`. При автоматизированном production update предыдущая программа переносится в отдельный recovery directory.

## Доказательства выпуска

До публикации exact source commit обязан пройти:

- `make verify`;
- `make test`;
- `make test-mail-release`;
- `make public-check`;
- version/lock/diff checks;
- Windows Tauri/NSIS build;
- isolated installed-artifact smoke;
- production deployment smoke с сохранением пользовательского state;
- GitHub macOS+Windows platform workflow;
- обратное скачивание и SHA-256-сравнение всех release assets.

Release tag `v0.29.3`, public `main`, `latest.json` и установленный `/api/version` должны ссылаться на один exact source commit. Если любой обязательный gate не проходит, выпуск не публикуется.
