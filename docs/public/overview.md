# Л.Е.С. — обзор для внешнего читателя

Л.Е.С. — локальная среда общих данных для строительных проектов. Он собирает документы,
таблицы, сметы, нормативы, переписку и CAD/BIM-данные в единый evidence-harness.

Обычный RAG отвечает “по похожим кускам текста”. Л.Е.С. строит путь ответа: понимает выбранный
датасет, находит нужные документы, вызывает табличные и сметные расчёты кодом, показывает
источники и честно фиксирует, чего не хватает.

## Что делает модель

- понимает вопрос и контекст проекта;
- выбирает workflow: RAG, таблицы, смета, нормоконтроль, CAD/BIM, сверка;
- раскладывает сложный запрос на инженерные шаги;
- задаёт уточнения, если данных недостаточно;
- пишет человеческий ответ.

## Что делает код

- хранит карточки файлов, evidence atoms, версии, graph facts и provenance;
- считает таблицы, сметы, ресурсы, НР/СП, своды и отчёты;
- проверяет единицы, применимость норм, missing prices and blockers;
- держит strict retrieval по выбранному файлу;
- не позволяет partial-результату выглядеть как защищённая финальная смета.

## Почему это полезно

В строительном проекте важна не только “красивая формулировка”, а доказуемая цепочка:

```text
документ / таблица / норма
  -> строка / пункт / ресурс
  -> расчёт или проверка
  -> источник и статус
  -> решение инженера
```

Л.Е.С. делает эту цепочку видимой. Если данных не хватает, он должен сказать “не хватает”,
а не дорисовать проект.

## Текущие сильные сценарии

- реестр и карта датасета;
- broad project overview по составам, ПЗ, ТЗ, инженерным томам;
- вопрос строго по выбранному файлу;
- табличные суммы по полным выгрузкам;
- ВОР/спецификации/сверки;
- ГЭСН/РИМ-позиции и ресурсные трассы;
- СПДС/normcontrol отчёты;
- CAD/BIM graph viewer на synthetic demo data.

## Граница честности

Л.Е.С. не обещает “автопроектировщика” или “автосметчика”. Он даёт модели инструменты,
память и источники, а код считает проверяемые части. Там, где нужны исходные данные,
экспертная привязка нормы или решение инженера, система должна это показать.
