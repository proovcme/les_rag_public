# Как устроен ЛЕС

ЛЕС помогает обсуждать проектные документы с языковой моделью, не теряя связь с исходными файлами. Это не одна программа, которая обязана держать всё на одном компьютере, а несколько независимых ролей.

```text
Совушка
  → backend ЛЕС
      → документы, память и инструменты
      → Qdrant для dense+sparse поиска
      → выбранная модель ответов
      → отдельная модель эмбеддингов
```

Совушка может находиться рядом с backend или подключаться к нему по сети. Модель также может работать локально, на другом узле LAN/ZeroTier или в явно настроенном облачном API.

## Что происходит при вопросе

1. Пользователь выбирает область: проект, датасет, файл или общий разрешённый контур.
2. Backend определяет допустимый workflow и собирает ограниченный контекст памяти.
3. Qdrant выполняет native RRF по именованным dense и BM25 sparse векторам; lexical channel страхует точные обозначения.
4. ЛЕС расширяет найденные фрагменты родительским и соседним контекстом.
5. Модель может выбрать один разрешённый инструмент через Registry → Broker → Executor.
6. Ответ возвращается вместе с источниками, пропусками и статусом результата.

Если Qdrant, модель или другой внешний компонент недоступен, соответствующая возможность получает явный статус. Core UI/API не должны падать только из-за отсутствующего внешнего сервиса.

## Ответственность компонентов

### Модель

- понимает вопрос;
- выбирает один разрешённый следующий шаг;
- связывает найденные сведения;
- формулирует ответ и уточнения.

### Код ЛЕС

- ограничивает доступ к данным;
- извлекает точные строки и карточки;
- выполняет воспроизводимые расчёты;
- хранит версии, provenance и evidence;
- не превращает догадку модели в подтверждённый факт.

### Человек

- выбирает источники и сетевые подключения;
- подтверждает профессиональное решение;
- оценивает применимость найденных данных;
- принимает ответственность за итоговый документ или расчёт.

## Что ЛЕС не обещает

ЛЕС не является автономным инженером, сметчиком или BIM-системой. Наличие специализированного модуля в репозитории не означает его готовность в production UI. Актуальные ограничения перечислены в [документе выпуска 0.29.3](releases/0.29.3.md).

## Данные

При локальной модели запросы могут оставаться внутри доверенной сети. При выборе облачного provider модель получает отправленный ей запрос и evidence-контекст. ЛЕС не должен менять локальный маршрут на облачный без явной настройки. Подробнее: [приватность и границы данных](privacy-and-data-boundaries.md).
