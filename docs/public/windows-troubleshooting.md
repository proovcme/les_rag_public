# ЛЕС на Windows: диагностика и восстановление

Это руководство относится к публичному `LES-Setup.exe`. Начинайте с безопасных проверок: они не меняют документы, настройки и индекс.

## Где смотреть состояние

| Что | Путь |
|---|---|
| Журнал первого запуска | `%LOCALAPPDATA%\LES\logs\bootstrap.log` |
| Машинный статус bootstrap | `%LOCALAPPDATA%\LES\logs\bootstrap-status.json` |
| Состояние процессов и портов | `%LOCALAPPDATA%\LES\logs\windows-light-state.json` |
| Ошибки API | `%LOCALAPPDATA%\LES\logs\windows-light-proxy.err.log` |
| Ошибки интерфейса | `%LOCALAPPDATA%\LES\logs\windows-light-ui.err.log` |
| Программа | `%LOCALAPPDATA%\Programs\LES` |
| Пользовательские данные | `%LOCALAPPDATA%\LES` |

Откройте `bootstrap-status.json` обычным Блокнотом. Поля `state`, `phase`, `code` и `message` показывают последний завершённый этап. Статус `ready` означает, что ядро ЛЕС запущено; массив `warnings` перечисляет недоступные внешние возможности.

## Коды первого запуска

| Код | Что произошло | Безопасная проверка | Действие | Ожидаемый результат |
|---|---|---|---|---|
| `bundled_runtime_unavailable` | Встроенный Python, uv, offline-cache или их контрольная сумма не совпали | Проверьте, что installer скачан из официального GitHub Release и его SHA совпадает с `.sha256` | Переустановите тот же или более новый полный выпуск поверх. Не устанавливайте Python/uv вручную | Bootstrap снова распакует встроенную среду; пользовательские данные сохранятся |
| `windows_state_helper_missing` | В дереве программы отсутствует модуль persistent state | Проверьте наличие `%LOCALAPPDATA%\Programs\LES\installers\windows\state.ps1` | Переустановите полный выпуск | Файл восстановится из installer payload |
| `windows_state_helper_failed` | Модуль состояния найден, но PowerShell не смог его загрузить | Посмотрите последние строки `bootstrap.log`; проверьте, не блокирует ли файл антивирус | Разрешите официальный файл в антивирусе либо переустановите выпуск | Инициализация `%LOCALAPPDATA%\LES` завершается |
| `les_init_failed` | Не создан Windows-профиль и каталоги ЛЕС | Проверьте свободное место и возможность записи в `%LOCALAPPDATA%\LES` | Освободите место, закройте процессы, повторите запуск | Появляется `.env` и рабочие каталоги состояния |
| `services_state_missing` | Службы стартовали без файла состояния | Проверьте `windows-light-*.err.log` и занятые порты ниже | Закройте старый ЛЕС, нажмите «Повторить подготовку» | Создаётся `windows-light-state.json` |
| `services_api_not_ready` | API не ответил за ограниченное время | Откройте proxy error log; проверьте порты и антивирус | Устраните указанную ошибку и повторите запуск | `/api/health` отвечает, интерфейс открывается |
| `services_start_failed` | PowerShell не смог поднять процессы ЛЕС | Смотрите вложенную причину и оба error log | Исправьте конкретную причину; переустановка нужна только при повреждении программы | Proxy и UI получают живые PID |
| `bootstrap_unhandled` | Неожиданная ошибка bootstrap | Сохраните `bootstrap.log` и `bootstrap-status.json` | Повторите один раз; если код возвращается, приложите оба файла к issue | Повторяемая ошибка получает диагностические материалы |
| `bootstrap_degraded` | Ядро работает, но одна или несколько внешних возможностей недоступны | Посмотрите массив `warnings` | Настройте нужный компонент внутри ЛЕС или оставьте функцию выключенной | ЛЕС остаётся доступен, предупреждение исчезает после проверки |

## Предупреждения внешних компонентов

### `answer_engine_unavailable`

Симптом: интерфейс открыт, но чат не может сгенерировать ответ.

1. Откройте «Конфигурация → Модели».
2. Выберите реально работающий Ollama, FreeToken, Lemonade или OpenAI-compatible endpoint.
3. Проверьте URL и название модели средствами самого выбранного продукта.
4. Сохраните настройки и повторите короткий запрос.

ЛЕС не устанавливает и не запускает эти продукты автоматически.

### `embedding_engine_unavailable`

Симптом: модель отвечает без поиска либо загрузка датасета не может построить векторы.

- Ollama-профиль: сервер Ollama должен отвечать, а embedding-модель `bge-m3` должна быть доступна.
- FreeToken-профиль: FreeToken даёт ответы, но текущему Windows-контуру нужен отдельный embedding-провайдер.
- Lemonade-профиль: проверьте Lemonade Server и адаптер, отображаемый в диагностике ЛЕС.

Не меняйте размерность существующей Qdrant-коллекции вручную. Несовместимый embedding-контракт требует отдельной generation/reindex-процедуры.

### `qdrant_unavailable`

Симптом: ЛЕС открывается, но поиск и индексация документов недоступны.

1. Если используете локальный Qdrant через Docker Desktop, завершите его первоначальную настройку и запустите Docker самостоятельно.
2. Проверьте в браузере `http://127.0.0.1:6333/collections`.
3. Вернитесь в экран настройки ЛЕС и нажмите «Проверить снова».

Не удаляйте контейнер `les-light-qdrant` или volume `les-qdrant-data` ради обычного перезапуска: volume содержит индекс пользователя.

## Типовые симптомы

### Окно не появляется

- Проверьте значок ЛЕС в трее: окно могло быть скрыто.
- Запустите ярлык ещё раз; single-instance guard должен поднять существующее окно.
- Если нет ни окна, ни статуса, проверьте защиту Windows и наличие WebView2 Runtime.
- Переустановите WebView2 с официального сайта Microsoft, затем повторно запустите ЛЕС.

### Подготовка долго стоит на одном этапе

Первое развёртывание встроенной среды может занять несколько минут из-за распаковки большого offline-cache и проверки файлов. Смотрите `phase` и время `updated_at` в `bootstrap-status.json`. Если время не меняется более десяти минут и нагрузка диска нулевая, закройте ЛЕС, сохраните журналы и повторите один раз.

### Порт 8050 или 8051 занят

ЛЕС умеет выбрать следующий свободный порт и записывает фактические URL в `windows-light-state.json`. Если порт удерживает старый процесс ЛЕС, обычный перезапуск завершит только подтверждённый LES-owned PID. Чужой процесс автоматически не уничтожается. Закройте приложение-владельца порта либо измените его настройки.

### После обновления остались старые документы или настройки

Это штатно: обновление заменяет `%LOCALAPPDATA%\Programs\LES`, но сохраняет `%LOCALAPPDATA%\LES`. Версия программы проверяется в интерфейсе или через `/api/version`. Старые пользовательские данные не являются признаком неудачного обновления.

### После обновления показывается старая версия

1. Полностью закройте окно и трей ЛЕС.
2. Запустите установленный файл из `%LOCALAPPDATA%\Programs\LES`, а не старую копию installer или ярлык из временной папки.
3. Повторно установите новый `LES-Setup.exe` поверх и проверьте `/api/version`.

## Переустановка и удаление

Обычная переустановка поверх сохраняет `%LOCALAPPDATA%\LES`. Для удаления программы используйте «Параметры Windows → Приложения → ЛЕС» и выберите сохранение данных.

Полное удаление данных необратимо: исчезнут документы, история, настройки и локальный индекс. Используйте его только по явному решению владельца и предварительно сохраните необходимые файлы. Не удаляйте `%LOCALAPPDATA%\LES` вручную по совету из случайного issue.

## Что приложить к сообщению об ошибке

- версию ЛЕС и Windows;
- точный `code` и `phase` из `bootstrap-status.json`;
- последние относящиеся к ошибке строки `bootstrap.log`;
- название выбранного провайдера без API-ключей;
- воспроизводится ли ошибка после одного повторного запуска.

Не публикуйте `.env`, API-ключи, документы проекта, полные пути заказчика или содержимое пользовательской базы.
