# Входной контроль ПД/РД Glorax

## Что это

Это рабочий профиль нормоконтроля поверх общего контура ЛЕС. Он проверяет комплект проектной
или рабочей документации по корпоративному перечню Glorax, показывает найденные основания и
передаёт окончательное решение инженеру.

Модуль не объявляет весь проект «соответствующим» или «не соответствующим». Его результат —
построчная ведомость: что проверялось, что найдено в документах, какой предварительный вывод
получен и какое решение принял инженер.

## Как выглядит работа оператора

1. Оператор загружает или выбирает проиндексированный комплект ПД/РД.
2. Выбирает перечень:
   - ПД — 335 критериев по 10 разделам;
   - РД — 692 критерия по 26 разделам.
3. При необходимости добавляет отдельные датасеты с ТЗ, СТУ и изысканиями.
4. Может проверить весь комплект или только одну дисциплину.
5. ЛЕС проходит пункты и для каждого показывает:
   - evidence-статус;
   - точные ссылки на документы и фрагменты;
   - техническое пояснение проверки;
   - необходимость ручной проверки.
6. Инженер открывает строку, изучает основания и фиксирует собственное решение.
7. Результат выгружается в Excel, HTML или JSON.

Макет доступен в Совушке: **Инструменты → Входной контроль ПД и РД**.

## Как ЛЕС проверяет разные пункты

| Вид пункта | Что делает система |
|---|---|
| Наличие документа или раздела | Ищет подтверждение в содержимом, а не только в имени файла |
| Наличие расчёта | Находит расчётную книгу и проверяет наличие сохранённых формул |
| Числовое требование | Извлекает значение из найденного фрагмента, затем сравнивает его кодом |
| Сверка двух разделов | Требует подтверждение с обеих сторон; одного документа недостаточно |
| Требования СПДС | Использует общий нормоконтроль по ГОСТ Р 21.101-2026 |
| Состав ПД | Сверяет фактический комплект с профилем ПП РФ №87 |
| Пространственная или визуальная проверка | Передаёт пункт инженеру, пока нет надёжной геометрии или изображения |

## Защита от ложной уверенности

- Уверенный evidence-статус запрещён без ссылки на конкретный источник.
- Совпадение имени файла не считается подтверждением содержания.
- Если нужный фрагмент не найден, это «нужно проверить», а не автоматическое нарушение.
- Числовые сравнения и итоговые счётчики выполняет код.
- Решение инженера хранится отдельно и не переписывает исходный машинный прогон.
- Предыдущий прогон и основания остаются доступными для проверки.

## Архитектура

```text
комплект ПД/РД
  → корпоративный перечень вопросов
  → инвентарь файлов и состав по ПП №87
  → адресный поиск по тексту и таблицам
  → формальные проверки СПДС и числовые сравнения
  → построчные основания
  → evidence-статусы
  → решения инженера
  → Excel / HTML / JSON
```

Чек-лист задаёт вопросы, но не содержит ответы. Общий RAG ЛЕС ищет подтверждения в выбранном
комплекте. Типизированные читатели открывают таблицы и расчётные книги. Код выполняет только
формализуемые проверки. Модель формулирует профессиональное объяснение только в общем model-owned
контуре; checklist API и UI не подменяют её готовым текстом и не меняют решение инженера.

## Что уже работает

- нормализованные перечни ПД и РД;
- импорт исходного Excel-чек-листа в версионированный JSON;
- семь классов критериев;
- поиск подтверждений по содержимому;
- проверка расчётных книг;
- параметрические правила;
- двусторонняя междокументная сверка;
- повторное использование СПДС-нормоконтроля;
- проверка состава ПД по ПП РФ №87;
- сохранение прогонов и решений инженера;
- интерфейс Совушки;
- API и отчёты Excel, HTML, JSON;

## Текущие ограничения макета

- Полный прогон на 335 или 692 пункта пока выполняется одним запросом; для большой рабочей базы
  нужен фоновый диспетчер с видимым ходом выполнения и возобновлением.
- Пространственные и визуальные критерии остаются ручными до подключения CAD/BIM или устойчивого
  анализа листов.
- Формируется Excel/HTML/JSON, но ещё не DOCX/PDF по фирменной форме.
- Качество результата зависит от полноты индексации проекта и наличия текстового слоя/OCR.
- Корпоративные шаблоны Glorax готовы; подключение другого заказчика требует импорта его перечня,
  а не нового движка.

## Основные точки входа

- API: `GET /api/checklist-review/templates`, `POST /api/checklist-review/{dataset_id}/run`.
- Результат: `GET /api/checklist-review/{dataset_id}/runs/{run_id}`.
- Решение инженера: `POST .../items/{item_id}/decision`.
- Отчёт: `GET .../download?fmt=xlsx|html|json`.
- Интерфейс: `sovushka/checklist_review_panel.py`.
- Движок: `proxy/services/checklist_review_service.py`.
- Алгоритмическая спецификация: [ALGO-glorax-checklist-review.md](ALGO-glorax-checklist-review.md).
