# ЛЕС на Windows — установка, удаление, обновление

Для обычной работы нужен только `LES-Setup.exe`. Это тот же стиль, что у AnythingLLM:
двойной клик → мастер → ярлык. Без CLI, Git и PowerShell.

Канон lifecycle (для разработки и приёмки): [ALGO-windows-lifecycle.md](ALGO-windows-lifecycle.md).

## Пути

| Что | Где |
|---|---|
| Программа | `%LOCALAPPDATA%\Programs\LES` |
| Данные (сметы, документы, настройки, Python) | `%LOCALAPPDATA%\LES` |
| Удаление из Windows | Параметры → Приложения → **ЛЕС · Совушка** |

UAC / «от имени администратора» не нужны и не используются.

## Чистая установка

1. Скачайте `LES-Setup.exe` текущего выпуска.
2. Закройте ЛЕС, если он открыт (мастер сам остановит shell и службы, если сможет).
3. Запустите установщик, примите путь по умолчанию.
4. На финише оставьте «Запустить ЛЕС» или откройте ярлык с рабочего стола.
5. Первый запуск сам подготовит Python, проверит Ollama/Docker и поднимет Совушку.

## Обычное удаление (программа)

1. Параметры Windows → Приложения → **ЛЕС · Совушка** → Удалить.
2. На вопрос про данные выберите **Нет**, если хотите сохранить сметы и документы.
3. Удаляются только файлы программы и ярлыки. `%LOCALAPPDATA%\LES` остаётся.

## Полное удаление (программа + данные)

1. То же Удалить в параметрах Windows.
2. На вопрос про данные выберите **Да**.
3. Удаляются `%LOCALAPPDATA%\Programs\LES`, `%LOCALAPPDATA%\LES` и канонический контейнер/volume Qdrant `les-light-qdrant` / `les-qdrant-data` (если Docker доступен).

## Обновление поверх

Как у AnythingLLM: скачайте новый `LES-Setup.exe` и установите поверх текущей версии.

- Мастер останавливает запущенный ЛЕС.
- Дерево программы заменяется.
- `%LOCALAPPDATA%\LES` не трогается.
- После установки откройте ЛЕС как обычно.

Дополнительно в настройках Совушки могут быть кнопки:

- быстрое обновление с `les.ovc.me` (мягкий пакет файлов);
- полная переустановка выпуска (скачивание `LES-Setup.exe` и та же hard-транзакция).

Это удобство. Основной путь пользователя — новый Setup.

## Если чего-то не хватает

Setup **не должен** падать с «ошибка 1» из‑за Ollama/Docker/остановки служб.

- WebView2 — Setup/Tauri стараются поставить сами (`downloadBootstrapper` + winget).
- Ollama — Setup пробует `winget`; если не вышло, пишет ссылку в  
  `%LOCALAPPDATA%\LES\logs\setup-deps-missing.txt` и показывает понятное окно.
- Docker Desktop — Setup не ставит молча (тяжёлый продукт), а пишет ту же памятку.
- После этого откройте ЛЕС: мастер настройки повторит проверку.

## Перед чистой установкой (зомби)

Setup перед копированием файлов вызывает `preflight-install` в
`les-setup-helpers.ps1`:

1. убивает **все** `les-desktop.exe` (не только текущий INSTDIR);
2. останавливает LES python на 8050/8051 best-effort;
3. сносит деревья `%LOCALAPPDATA%\LES-removed-*` / `LES-purge-*` (rename → async delete);
4. чинит ярлыки на `%LOCALAPPDATA%\Programs\LES\les-desktop.exe`.

Ручной прогон:  
`powershell -File installers\windows\app\les-setup-helpers.ps1 preflight-install`

## Если что-то пошло не так

- Setup/Uninstall не должен завершаться кодом 1 из‑за `taskkill`/Docker/занятых файлов:  
  остановка и wipe — best-effort, при блокировке будет русское сообщение и путь папки.
- ЛЕС «не удаляется» — закройте окно и трей, повторите; либо удалите папку из сообщения вручную.
- После удаления без данных остался ярлык — удалите вручную; следующий Setup создаст новый.
- Ярлык с рабочего стола открывает «призрак» из `LES-removed-*` — снова Setup или
  `preflight-install`, затем канонический путь выше.
- Приёмка разработчика (smoke, git/VPS) — [INSTALL_RUNBOOK.md](INSTALL_RUNBOOK.md), не путь пользователя.
