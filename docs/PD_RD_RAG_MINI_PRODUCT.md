# PD/RD RAG Source Map — мини-продукт

## Коротко

Нам нужен не “RAG по PDF”, а предварительная карта ПД/РД. В проектной документации уже есть формальная структура: состав проекта, содержание тома, оглавление ПЗ, штампы, шифры, номера листов, исходные имена `.doc/.dwg`, количество листов. Это готовая навигационная база для модели.

`PD/RD RAG Source Map` снимает эту структуру в sidecar до чанкинга и поиска. Модель потом не бродит по случайным top chunks, а идёт по карте: раздел → том → тип документа → лист/раздел → retrieval → ответ по источникам.

## Что извлекаем

### Содержание тома

Многостраничный реестр состава тома:

- обозначение;
- наименование;
- примечание;
- раздел внутри содержания;
- лист;
- количество листов;
- declared total sheets;
- `source_ref`.

На полигоне ПД ИЦ том `ИОС.ЭС` дал `92` строки содержания на страницах `5-8`, declared total `242`.

### Состав проектной документации

Реестр всего проекта:

- номер тома;
- обозначение;
- название раздела/подраздела;
- `source_ref`.

На томе `ИОС.ЭС` после repair-pass прочитались страницы `9-12`, `49` строк: ИОС, ВК, ОВ, СС, ПБ, СМ и т.д.

### ПЗ

Важно: `.ПЗ` — это только тип документа, “пояснительная записка”. Это не домен. Домен берём из шифра, например `ИОС.ЭС`, а темы — из оглавления ПЗ.

Из ПЗ извлекаем:

- номер раздела;
- заголовок;
- целевой лист;
- `source_ref`.

На томе `ИОС.ЭС` оглавление ПЗ дало `32` пункта.

### Штампы и листы

Из листов:

- формат;
- наличие штампа;
- шифр и нормализованный `cipher_norm`;
- стадия;
- лист/листов;
- вид документа по хвосту шифра (`ПЗ`, `С`, `СП`, `СО`, `ВОР`);
- дисциплина/поддисциплина (`ИОС`, `ЭС`);
- имя исходного файла `.doc/.dwg`;
- название объекта/листа, где стабильно читается.

## Почему это мини-продукт

Потому что это отдельная ценность даже без полного LES:

1. Загружаешь том ПД/РД.
2. Получаешь JSON-карту документа.
3. Видишь состав проекта и тома.
4. Понимаешь, какие листы и разделы есть.
5. Можешь строить retrieval не по догадке, а по формальной структуре.

Это можно использовать как:

- sidecar для LES RAG;
- отдельный CLI-инструмент;
- UI-навигатор по ПД/РД;
- preprocessor для любого RAG;
- базу для будущего reader-а графической части.

## Принцип

Код не отвечает за модель. Код строит карту.

Модель:

- выбирает тему;
- выбирает документ/раздел/лист;
- вызывает tools/retrieval;
- читает источники;
- отвечает.

Код:

- извлекает структуру;
- нормализует шифры;
- считает листы;
- чинит text-layer mojibake;
- хранит provenance;
- показывает missing/conflicts.
